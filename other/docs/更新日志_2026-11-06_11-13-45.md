## 一、背景不时闪烁：程序自己写的字模缓存被当成「素材变化」

`hotreload` 盯的是整个素材目录，而**字模缓存 `assets/ui/text_cache/` 就在这个目录里**，
它是程序每渲染一句没见过的台词就写一张 PNG 的地方。

于是每来一句新台词 → 目录签名变了 → 2 秒后判定「素材变了」→ `gen+1` →
前端 `wt-hotreload.apply()` 调 `__reapplyBg()`（还会重拉立绘索引）→ 背景交叉淡化重画一次
→ **画面闪一下**。

实证（用户那一局的 `logs/app-20261106.log`）：70 秒内触发了 **10 代**；
我手动请求 2 次 `/api/text`，也立刻多出 2 代。

**修**：`hotreload.SKIP_DIRS` 加 `text_cache`（和 `sessions`/`cache`/`logs` 同理：
运行时数据，不是用户放的素材）。复测：连写 3 张新字模，`gen` 一直 0。

## 二、场景 CG 不换：演出标签提示只在「有云端 key」时才加

`api_chat._chat` 里那段【场景】【服装】【情绪】【格式】提示，以前整个包在 `if cc:` 里
（`cc = cloud_cfg()`）。跑**本地模型**时模型从来没被告知要输出 `<scene>`/`<outfit>`/`<emotion>`，
后端 `split_scene` / `scene_cg.match` 再准也没东西可匹配。

**修**：抽出 `api_chat.performance_hints(cc, outfit_hint)`：云端**和本地**都加
【场景】【服装】【情绪】【格式】；只有【语言】（只用日语）和【双语】（`<ja><zh>`）留给云端
——本地小模型做不好双语，硬要求反而写坏，中文由 `translate.py` 兜底。

## 三、立绘不变：角色包里没有 `portrait/index.json`

角色目录有 14 套衣服、每套几十张表情图，**但没有 `index.json`**（老版本导入的角色包不写），
`sprite_index()` 返回空 → 前端 `SPRITE_INDEX` 空 → `spritePath()` 每套衣服都查不到 →
永远 `assets/kaz_cold.png`。

**修**：`characters._scan_portrait_outfits()` —— 索引为空时照
`portrait/<衣服>/<表情>.png` 现扫一份（不写文件，加图下次自动生效）。
写了 `index.json` 的仍以文件为准。修前接口返回 `outfits: {}`，修后 **14 套**。

顺带修一个合并 bug：自带索引按编号、角色索引按中文名时，改名分支把
**自带那套的表情映射整段丢了**（注释写着要叠加，代码读的位置不对）。

## 四、表情永远同一张：情绪名跟素材对不上

模型给的 `<emotion>` 是 `calm / soft / 毒舌 / 撒娇 / 哭腔 / 调侃吐槽 / 问句`，
程序 `detectMood` 给英文，而素材里的表情名是中文（认真/微笑/生气/冷淡/惊讶/害羞/难过/其他）。
`MOOD_TO_EMO` 映射到的英文名在素材里不存在 → 一律退「认真」→ 换情绪等于没换。

**修**：`wt-sprite.js` 加 `EMO_ALIAS` 按顺序逐个试（原名 → 角色覆盖表 → `MOOD_TO_EMO` → 别名）：

| 给的 | 用素材里的 |
|---|---|
| `calm` / `问句` | 认真 |
| `soft` / `warm` / `smile` / `撒娇` / `调侃吐槽` | 微笑 |
| `毒舌` / `cold` | 冷淡 |
| `angry` | 生气 |
| `sad` / `哭腔` | 难过 |
| `惊讶` / `shy` | 惊讶 / 害羞 |

## 五、BGM 不变：`detectMood` 是全中文正则，却喂了日语原文

`accumulateMood(reply)` 里的 `reply` 是**日语原句**，而 `detectMood()` 的关键词
（滚/烦/早点睡/对不起…）全是中文，一个都不命中 → 永远 `calm` → 永远不换歌。
（双语改造之前 `reply` 是中文译文，所以以前是好的。）

**修**：`accumulateMood(replyZh || shown)`。切换门槛没动（0.65 衰减 + 连续两轮领先 2 分）。

## 六、分支数量设置不生效：读了不存在的 `WA2.prefs`

设置里把「选择分支数量」改成 3/4/5，出来的永远是 **2 个**。

`wt-choices.js` 的 `prefsCount()` 读的是 `WA2.prefs.getPrefs()`，而**这个对象从来没定义过**
——设置模块的真实入口是 `window.App.getPrefs/setPref`。读不到就回落默认 2，
于是每次请求 `/api/choice` 都带 `count: 2`，后端按 count 生成也只有 2 个。

`menubar.js` 的 `setChoiceCount()` 同样先试 `WA2.prefs.setPref`，落空后走自己拼的兜底
（localStorage + POST `/api/prefs`）——所以**设置其实存进去了**（用户 `prefs.json` 里
`choiceCount: 5` 就是他最后选的值），只是读的那侧永远拿不到。

**修**：两处都改用 `window.App`（读 `getPrefs` / 写 `setPref`），保留兜底，App 未就绪回落 2。
