# 重要参考：这个项目里踩过的坑（拆模块 / 路由 / 前端）

> 这份文档只记**会重复犯**的错。每条都写明「现象 → 根因 → 正确做法」，
> 改代码前先扫一遍标题，能省掉一整轮来回。

## 一、拆模块：全局变量会「变私有」

**现象**：把 `main.py` 里的函数拆到 `winutil.py` 之后，窗口拖动、最大化全部失效，
但注释里看不出任何问题。

**根因**：

```python
# 拆之前（同一个文件，没问题）
def _win_hwnd():
    w = globals().get("_WINDOW")      # ✅ 能拿到

# 拆之后（winutil.py 里）
def _win_hwnd():
    w = globals().get("_WINDOW")      # ❌ winutil 的 globals() 里没有 _WINDOW
```

`globals()` 返回的是**当前模块**的命名空间。函数搬走后，原来「同一个文件所以能看见」
的全局变量就全部看不见了，而这些变量不会报 `NameError`（因为是 `.get()`），
只会静默返回 `None` —— 表现是「功能没反应」，不是「报错」。

**正确做法**：拆出去的函数如果要访问主模块的全局，显式跨模块取：

```python
def _main_module():
    import sys
    for name in ("main", "__main__"):
        m = sys.modules.get(name)
        if m is not None and getattr(m, "_WINDOW", None) is not None:
            return m
    ...
```

## 二、`python main.py` 的主模块名是 `__main__`，不是 `main`

**现象**：按上一条改成 `sys.modules.get("main")` 之后，**问题依旧**。

**根因**：

| 启动方式 | 主模块在 `sys.modules` 里的名字 |
|---|---|
| `python main.py` | **`__main__`** |
| `import main`（被别的模块导入） | `main` |

直接跑脚本时，Python 把主文件注册成 `__main__`。所以只查 `"main"` 永远取不到。

**正确做法**：两个名字都查，且**优先返回真的持有目标变量的那个**（否则可能拿到一个空壳模块）。

**排查手法**：这类问题的特征是「代码看着对、变量不报错、功能静默失效」。
最快的定位方式是**打日志把关键值打出来**——比如在 `drag_begin` 里打印 `hw` 的值，
一眼就能看出是 0 还是真实句柄。

## 三、按行号插代码：`ast.parse` 查不出死代码

**现象**：存档列表接口 404，日志里反复出现 `GET /api/session/list -> 404`，
但文件里明明写着这条路由。

**根因**：用脚本按行号插入代码时，缩进多了一层：

```python
if self.path.startswith("/api/session/load"):
    return self._json(session_load(...))
    if self.path.startswith("/api/session/list"):   # ← 多缩进，成了 return 之后的死代码
        return self._json(session_list())
```

`ast.parse` 完全通过——语法没错，只是**永远执行不到**。

**正确做法**：

1. 按行号改完，**必须回读那几行确认缩进层级**
2. 改完立刻起服务打一次接口，看返回码（不只是看能不能启动）
3. 宁可多写一次 `git diff`，也别信「语法通过 = 改对了」

## 四、改前端之前，先读 HTML 的真实结构

**现象**：把覆盖确认框的文案接上字模后，第一行显示错内容、第二行变成系统字体。

**根因**：那是个**两行**结构

```html
<div class="txt t1" id="dlgConfirmT1">存档将被覆盖。</div>
<div class="txt t2" id="dlgConfirmT2">确定吗？</div>
```

我按「一句话」处理，把合成图塞进第一行，同时删掉了第二行原来的渲染调用。

**正确做法**：动任何界面文案前，先 `grep` 一下 HTML 里那段，确认：

- 是一行还是多行
- 是文本节点、`<input placeholder>`，还是 `<img>`
- 文案是写死的还是 JS 动态改的（动态的不能一次性替换）

`<input placeholder>` **不能用图片**，只能走渲染接口——这类限制读一眼 HTML 就能发现。

## 五、字模尺寸：显示高度 ≠ 字号

**现象**：把字模 PNG 按 15px 显示，看起来比正文明显大。

**根因**：字模渲染器参数是固定的：

```
FONT_SIZE       = 28   字形本身
FONT_STROKE     = 2    描边
出图高度         = 32   （含描边）
```

一张 32px 高的图里装着一个 28px 的字，实际字形可能只有 29~31px。
所以**显示高度要用实测字形高换算**：

```
显示高度 = CSS 字号 × 图高 / 实测字形高
```

**实测方法**（`PIL` + `numpy` 扫 alpha 通道的非透明行范围）：

| 图 | 图高 | 实测字形 | 15px 正文对应显示高度 |
|---|---|---|---|
| save_over | 32 | 30 | 16.0 |
| load_empty | 32 | 31 | **15.5** |
| save_done | 32 | 29 | 16.6 |

**正确做法**：先量，再定高度。别用「字号 × 32/28」硬算（会偏大约 5~10%）。

## 六、WebView2 上 `transform` 过渡失效（待确认）

**现象**：给界面加交叉缩放淡入淡出，代码写了、类加上了，但视觉上毫无变化。

**实测**（iframe 内每 25ms 采样 `getComputedStyle`）：

| 属性 | 结果 |
|---|---|
| `opacity` 过渡 | ✅ 能采到 12 个渐变值 |
| `transform: scale()` + transition | ❌ 恒为 `matrix(1, 0, 0, 1, 0, 0)` |
| `transform` + `@keyframes` | ❌ 同上 |

已排除：缓存、内联样式压制、写法问题、元素不可见。

**当前状态**：结论未定。下一步要用 **WAAPI**（`element.animate()`）验证——
它能直接拿到 `playState` / `currentTime`，可以区分「动画没执行」还是
「执行了但渲染层丢弃」，这两种情况的修法完全不同。

> 朋友的建议（记下来）：
> 「先定位为什么这个 transform 没变，别直接就找绕过 GPU 合成层的方法。」

## 七、浏览器 Fullscreen API 不能用（无边框窗口）

**现象**：点「全屏模式」后，窗口铺满屏幕但**整个桌面点不动**，
光标能移动、键盘能输入，只有粘滞键那种系统级窗口能点。

**根因**：

```js
document.documentElement.requestFullscreen()   // ❌ 网页全屏
```

它只让 WebView 以为自己全屏了，**宿主窗口的尺寸和样式没变**，
结果是一个没有边框、接收鼠标事件、但内容不铺满的透明层盖住桌面。

**正确做法**：改窗口本身，不改网页：

```python
w.toggle_fullscreen()      # pywebview 原生
# 失败则退回 w.maximize()
```

## 八、测试环境 `--serve-only` 起不来的问题

**现象**：`python main.py --serve-only --port 8791` 启动后进程活着，
但端口没有监听（`Get-NetTCPConnection` 查不到 Listen），`curl` 返回 000。

**影响**：这一整轮里多次导致「改完没法自测」，只能靠用户截图验证，
也因此浪费了大量来回。

**待查方向**：启动流程里 `serve_only()` 之前的某一步卡住（剧情索引预热 / 模型探测）。

**正确做法（在下一次修复之前）**：

- 自测优先用**不依赖 HTTP** 的方式（直接 `import` 模块调函数，
  如 `import sessions; sessions.session_list()`）
- 需要 HTTP 时，先确认进程在监听再发请求，别盲等

## 九、通用原则（从前八条里抽出来的）

1. **改完必须验证「执行路径」**，不是「文件里有这行代码」
2. **静默失效比报错更危险**——`.get()`、`try/except`、`|| fallback` 会把错误吃掉
3. **拆模块的本质是打破隐式共享**，所有 `globals()` / 自由变量都是待爆的雷
4. **动界面前先读结构**（HTML 是几行、是文本还是图、是静态还是动态）
5. **尺寸、颜色这类视觉参数，量出来再写**，别算
6. **一个方案连试三次不生效，就换一种观测手段**（采样、日志、WAAPI 状态）

## 十、删函数时留下 `''` 占位，会让整个文件"半死"

**现象**：右键没反应、「全体音量」「VOICE」滑块拖了没用，但其它功能都正常。

**根因**：清理死函数 `fadeSwap` 时删掉了函数体，留在原地的只有一个 `''`：

```js
window.fadeInScreen = function (el, ms) { ... };
''                        // ← 残留
(function () { ... })();
```

`''` 后面紧跟 `(` 会被解析成**函数调用**：`''(function(){...})()` →
`TypeError: "" is not a function`，**文件从这里就断了**，后面 56 行一条都没执行。

**正确做法**：删函数连"空占位"一起删；改完看一眼控制台有没有 `TypeError`，
再用 `tools/ui_probe.py` 打一次关键路径。这类错误的特征是**"只有某几块功能没了"**，
很容易被误判成"那段代码写错了"，其实那段代码根本没跑。

## 十一、同一件事有两种坏法：`ReferenceError` + `try/catch`

**现象**：OPTION 2 的开关点了有高亮，但退出再进又复原；音量拖了不生效。

**根因**：`CT2`（控件表）定义在 IIFE 里，而文件末尾的 `applyCt2()` / 启动还原在 IIFE 外面，
读它直接 `ReferenceError`；调用处还包着 `try { } catch (e) {}`，于是**一声不响**。

**正确做法**：跨 IIFE 共享的表/状态显式挂到 `window` 或提到文件顶层；
`try/catch` 至少打一行 `console.warn`，否则等于把 bug 藏起来。

## 十二、`getComputedStyle` 在 class 刚改完时读的是"过渡前"的值

**现象**：验证「隐藏界面」时，`msgWrap` 的 opacity 是 0，`inputBar` 却是 1，看起来像选择器写错。

**根因**：`#inputBar` 上挂着 `transition`，改完 class **同一帧**读 `getComputedStyle`
返回的是**过渡起点**。没有过渡的元素（`msgWrap`）才会立刻返回目标值。

**正确做法**：等过渡结束再读（`ui_probe.py` 把"读"放到 `--check`）；
另外探针窗口被遮挡时 `requestAnimationFrame` 会被节流到不触发，
采样要用 `setInterval`。

## 十三、这台机器上 `transform` 完全不可用，但 `zoom` 可以

**实测**（真实 WebView2，普通 div，逐帧采样 `getComputedStyle`）：

| 属性 | 结果 |
|---|---|
| `transform` | ❌ 恒为 `none`，**连静态值都被丢弃**（不只是过渡失效） |
| `filter: blur()` | ✅ 20 种渐变值 |
| `zoom` | ✅ 20 种渐变值 |
| `opacity` | ✅ 20 种渐变值 |

**结论**：要做"收缩"动画用 `zoom`；`transform: scale()` 在这台机器上别指望。
之前"WAAPI 把槽位弄没"更像是 `fill: forwards` 的内联样式压住了重绘，不是 WAAPI 本身的问题。

## 十四、`--serve-only` 端口不响应：Windows 的 `SO_REUSEADDR`


**现象**：`--serve-only` 启动后进程活着，但端口不监听 / 连不上。

**根因**：Python 的 `HTTPServer.allow_reuse_address` 在 Windows 上等价于
`SO_REUSEADDR`，它**允许两个进程绑同一个端口**。于是第二个实例"绑定成功"、
监听表里也能查到，但连接全被前一个进程吃掉 —— 看起来就是"起来了但没反应"。

**正确做法**：`allow_reuse_address = False`（见 `main.py` 的 `_Server`），
让绑定失败能正常抛 `OSError`，从而落到 8772 / 随机端口。
排查时用 `Get-NetTCPConnection -State Listen | ? OwningProcess -in $pids` 看**同一个端口是不是被两个 PID 同时持有**。

## 十五、控件图按索引命名：删行不能重新编号

**现象**：OPTION 1 删掉两行选项后，改数字按钮/画面特效的图全串了。

**根因**：`assets/ui/opt/ct/w00..w21_sel.png` 是**按控件在数组里的索引**命名的。
删掉中间的条目再重新编号，第 6 个控件就会去拿 `w06`（原本是「全文」）的图。

**正确做法**：被删的位置在数组里留 `null`，创建图片、贴图、建热区时跳过；
索引永远不动。

**排查手法**：界面上一眼看出"按钮长得不像它该有的样子"，先去看贴图是不是按索引取的。

## 十六、样式表里的 `!important` 会压过普通内联样式

**现象**：用 JS 给输入栏设 `style.opacity`，消息框跟着变透明了，输入栏纹丝不动。

**根因**：`game450.css` 末尾有 `#inputBar { opacity: 1 !important }`。
层叠顺序里**作者的 `!important` 高于普通内联样式**，所以内联的 `opacity: 0.4` 被忽略。

**正确做法**：`el.style.setProperty("opacity", v, "important")`（内联 `!important` 才是最高优先级）。
量的时候记得看 `getComputedStyle`，别只看 `el.style`。

## 十七、逐字显示一张图：`clip-path` + 固定排版网格

**问题**：正文是服务端渲染成一张 PNG 的，想"一个字一个字冒出来"，又不能一个字一张图。

**做法**：`sub_render.py` 的排版是固定网格——每字 32×32、水平步进 28px、每行 20 字、行高 32px。
所以「显示到第 k 个字」可以直接换算成裁剪区域：上面几行整行可见，当前行只显示到第 N 个字，
一个 `clip-path: polygon()` 就够，且不会重新排版。

**必须自检**：算出来的行数和图高对不上（例如文本里有换行符）就**放弃动画**、整段直接显示，
判据是 `|图高 - 行数×32| <= 2`。宁可不动画，也不能把字裁掉一半。
