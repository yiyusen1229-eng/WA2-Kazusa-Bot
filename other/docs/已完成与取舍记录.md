### #10 角色包导出 / 导入（2026-11-04）

**结论**：做完。特别模式 → 配置角色 → 「导出 / 导入」，角色可以打包成 zip 带走。

**依据**
- `program/src/char_pack.py`：打包、解包、校验、系统窗口
- `program/src/api_charpack.py`：`POST /api/charpack/export`、`/api/charpack/import`
- `program/src/ui/sp-pack.js`：两个按钮（底板复用发送按钮的 `btn_3state.png`）
- `program/tools/test_char_pack.py`：44 项自测

**范围**：只带 `name.txt` + `prompt/ worldbook/ memory/ portrait/ voice/` + `manifest.json`。
不带 `sessions/`（存档）、`story.json`、`tts.json`、`opening.json`、`pronunciation.json`、缓存。

**代价 / 边界**
- 不能靠角色包搬家存档（存档留在本机）。
- 导入不自动切换角色，要自己点「切换角色」。
- 没有 `tts.json` 的权重路径，换机后音色要靠 `voice/` 参考音频重建。

**验证**：真实角色 360 文件 / 103.6MB，导出 0.2s、导入 0.2s，五类资源数量全部对上。

### #16 密钥安全与日志脱敏（2026-11-04）

**结论**：做完。key 优先读环境变量，日志写之前统一脱敏，界面只显示掩码。

**依据**
- `program/src/secret.py`：`env_key()`（`WA2_API_KEY` > `DEEPSEEK_API_KEY`）、`apply_env()`、`mask()`、`is_masked()`、`redact()`
- `main.cloud_cfg()`：环境变量优先于 `config.json`；文件里那份保留，去掉环境变量就回落
- `main.model_cfg_all()`：key 来自环境变量时只返回 `sk-****abcd` + `key_from_env: true`
- `main.model_cfg_save()`：收到掩码就保留原 key，不会把 `****` 写进文件（扁平字段和 `models.chat` 两种结构都兜住）
- `applog.log()` / `main.log()`：写之前过 `redact()`，抹掉 `sk-...`、`Bearer ...`、`"api_key": "..."` 的值
- `config.example.json`：`api_key` 留空，`_note` 说明可以改用环境变量
- `program/tools/test_secret.py`：24 项自测

**边界**
- 只做环境变量，没接系统密钥链（keyring）。
- 已有的明文 key 不自动迁移（避免写坏配置）。
- 环境变量只管 key；`base_url` / `model` 仍然来自 `config.json`。
- 日志里本来就不写对话正文，这次只管「长得像密钥」的东西。

**验证**：24 项自测全绿；起服务设 `WA2_API_KEY` 后 `GET /api/modelcfg` 只回 `sk-****7890` + `key_from_env: true`；用掩码保存不会覆盖文件里的真 key。

### #9 角色切换过渡（2026-11-04）

**结论**：做完。切角色不再是「啪」一下换人，而是**压黑 → 换人 → 淡回**。

**依据**
- `ui/sp-char.js`：`doSwitchCharacter()` 改成「存会话 → 压黑 → 切换 → 淡回」，新增 `fadeOn/fadeOff/setInputEnabled/saveBeforeSwitch`
- `ui/index.html`：`#charFade` 整幕黑层（z-index 200，在 `.uiScreen` 120 之上、标题栏之下）
- `ui/game450.css`：压黑 180ms、淡回 200ms；请求超过 420ms 才在中间显示角色名
- `ui/wt-session.js`：`sessionSave()` 改为返回 promise —— 切换前必须等这一笔写完，否则会存进新角色的目录
- `ui/wt-chat.js`：`send()` 在 `__charSwitching` 时直接返回

**边界**
- 没做进度条：切换是本地改文件，正常 <50ms，只有慢的时候才显示名字。
- 不关特别模式面板：切换完仍留在面板里，名字与资源已经刷新。
- 切换失败：淡回原角色 + 提示，不留黑屏。

**验证**：探针记录 `before:"" → t50:on → t200:on → t900:""`，`inputDisabled` 恢复 false、`switching` 清除、`active.json` 从 A 变成 B。

## 换了做法了结

### #1 缓存隔离与淘汰 → 改成「启动全清 + key 带角色」

**结论**：**不按原方案**做 `cache/<角色>/` 分层与 LRU。原方案要解决的问题（切角色串音、硬盘失控）已经用更省事的办法解决。

**实际做法**
- 启动时清空文字渲染缓存、TTS 缓存、记忆运行时（`main.py` 的 `main()` 开头三连）。
- TTS 缓存 key 里带角色 id 与参考音频目录签名（`tts_client._char_voice_sig`），换角色必失效。

**解决了的**
- 切角色不会听到 / 看到上一个角色的内容（这是原方案最在意的点）。
- 硬盘不会越用越大。

**代价**
- 每次开程序，第一句语音都要重新合成；第一次进游戏的字模要重渲染。**这是有意的取舍，不是 bug。**

**还没做的**（写在路线图 #1 里）：跨启动保留、按角色分层、体积上限。只有「每次启动重合成」真的变成问题时才值得回头做。

### #4 关系阶段回退 / 漂移检测 → 明确不做

**结论**：**只升不降**，到 4（婚后 / 同居）封顶，不再调用分类。

**理由**
- 本地关键词判断不准，所以改成每 40 轮云端判一次。
- 回退容易在「今天冷淡 / 明天热络」之间抖动，反而破坏体验；用户明确选择了「只升不降」。

**依据**：`persona_stage.py` 头部注释（2026-11-02 按用户要求改）；分类在后台线程跑，结果下一轮生效；状态存 `cache/persona_stage.json`，不写存档。

**代价**：长期不互动时关系不会降，可能失真。**接受这个失真。**

**注意**：以后不要再提「加回退」，除非用户明确要。
