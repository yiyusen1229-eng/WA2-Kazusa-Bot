### #7 多模态过渡：交叉淡化 / 响度归一化 / 设备变化（2026-11-05）

**结论**：做完。背景和立绘改成双缓冲交叉淡化（200~300ms，可关）；TTS 每次合成量一次响度、
把增益应用到发出去的字节上（磁盘 wav 不动，增益记在侧车）；拔耳机 / 切蓝牙后自动暂停 → 重建 → 续播。

**依据**
- `program/src/ui/wt-fade.js`：`WA2.fade`（`enabled/ms/set/crossBg/crossSprite/settle`）。
  背景两层 `#bgLayer` + `#bgLayer2` 轮换淡入，过渡完把图搬回 `#bgLayer`（别的代码读它不会读到旧值）；
  立绘用 `#spriteGhost` 叠一层新图淡入，淡完再把主图换掉。
- `program/src/audio_gain.py`：BS.1770 近似的响度测量（K 加权两级 biquad + -70/-10 门限），
  峰值保护（最多推到 -1 dBFS），增益夹在 ±12 dB。
- `program/src/api_tts.py`：响应头 `X-Voice-Gain-DB` / `X-Voice-Lufs`，字节在发出去之前缩放。
- `program/src/tts_client.py`：`_record_gain()` 在 `cache/tts/<hash>.wav.gain.json` 记
  `{target, lufs, peak_db, gain_db, applied, bytes, at}`；wav 本身一个字节不改。
- `program/src/ui/wt-audio.js`：`devicechange` → 立即暂停 → 600ms → 重建 `Audio` 元素续播；
  续不上走 `__saveHint` 提示「重播这句」。`program/src/ui/wt-voice.js`：`suspendForDevice/resumeAfterDevice`。
- 开关：顶部菜单「环境设置 → 演出过渡（交叉淡化 / 直接切换）」，写 `prefs.json` 的 `xfade`。
- 自测：`tools/test_fade.js`（24 项，Node）、`tools/test_audio_gain.py`（28 项）；
  另加 `tools/test_ui_syntax.js`（44 个前端文件，`vm.Script` 只解析不执行——`check_split.py` 是正则扫的，
  注释把函数吞掉这类语法错它看不出来）。

**代价 / 边界**
- 关过渡 = 直接切，没有中间态（不是「慢一点的淡入」）。
- 每次换图多一次预载（先 `new Image()` 再淡），换来的是不会闪出破图。
- 响度归一化在服务端做，新合成 / 首次命中缓存各多几十毫秒（同一段字节第二次是内存命中）。
- 只认 16bit PCM wav；别的格式原样放过、增益记 0（不猜、不硬改）。
- 设备变化只在浏览器给 `devicechange` 时才有动作；系统静默换默认设备不会触发。

**验证**：探针（不截图）确认双层交替、收尾把图搬回 `#bgLayer`、立绘叠层淡入后主图 `naturalWidth=462`、
关掉后 `#bgLayer2` 保持 `none`、`devicechange` 计数 0→1 且无 JS 报错；
真实 `/api/tts` 请求返回 `X-Voice-Gain-DB: 0.79`、`X-Voice-Lufs: -16.0`，磁盘缓存仍是 -16.79 LUFS（字节未改）。

**依据**

### #2 演出状态机冲突仲裁（2026-11-05）

**结论**：做完。重播 / 流式输出 / 浮层 / 切角色收成一个状态机，冲突有统一规则。

**依据**
- `ui/wt-perf.js`：`WA2.perf`，状态 `IDLE / DIALOGUE_STREAMING / VOICE_PLAYING / REPLAYING / OVERLAY_OPEN / CHARACTER_SWITCHING`，按占用计数（可嵌套）+ 固定优先级
- `wt-chat.js`：发消息先掐重播、停语音，再进 `DIALOGUE_STREAMING`，`finally` 里退出
- `wt-backlog.js`：重播前 `can("REPLAYING")` 判断，进出都登记；`done` 只结算一次
- `screens.js`：浮层开关统一走 `syncOverlay()`，按 DOM 推导，不逐次计数
- `sp-char.js`：切角色进 `CHARACTER_SWITCHING`，同时停语音、关浮层
- 自测：`tools/test_perf.js`（18 项，Node）+ 探针实机验证

**规则**
- 新消息打断重播（先 `interrupt` + 停语音）
- 切角色 / 流式输出时不许重播
- 浮层不算忙：回想本身就在浮层里，重播照常
- 计数而不是布尔，嵌套调用不会提前归零；多余的 `end` 不会把计数弄负

**边界**
- `VOICE_PLAYING` 目前只登记状态，没拿它做互斥（同一时刻只有一路语音）。
- 浮层状态是「按 DOM 推导」，不靠逐次计数 —— 谁都能关浮层，也不会把计数弄乱。

## 换了做法了结

### #1 缓存隔离与淘汰 → 改成「启动全清 + key 带角色」

**结论**：**不按原方案**做 `cache/<角色>/` 分层与 LRU。原方案要解决的问题（切角色串音、硬盘失控）已经用更省事的办法解决。

**实际做法**
- 启动时清空文字渲染缓存、TTS 缓存、记忆运行时（`main.py` 的 `main()` 开头三连）。
- TTS 缓存 key 里带角色 id 与参考音频目录签名（`tts_client._char_voice_sig`），换角色必失效。

**解决了的**
- 切角色不会听到 / 看到上一个角色的内容（这是原方案最在意的点）。
- 硬盘不会越用越大。

**代价**
- 每次开程序，第一句语音都要重新合成；第一次进游戏的字模要重渲染。**这是有意的取舍，不是 bug。**

**还没做的**（写在路线图 #1 里）：跨启动保留、按角色分层、体积上限。只有「每次启动重合成」真的变成问题时才值得回头做。

### #4 关系阶段回退 / 漂移检测 → 明确不做

**结论**：**只升不降**，到 4（婚后 / 同居）封顶，不再调用分类。

**理由**
- 本地关键词判断不准，所以改成每 40 轮云端判一次。
- 回退容易在「今天冷淡 / 明天热络」之间抖动，反而破坏体验；用户明确选择了「只升不降」。

**依据**：`persona_stage.py` 头部注释（2026-11-02 按用户要求改）；分类在后台线程跑，结果下一轮生效；状态存 `cache/persona_stage.json`，不写存档。

**代价**：长期不互动时关系不会降，可能失真。**接受这个失真。**

**注意**：以后不要再提「加回退」，除非用户明确要。
