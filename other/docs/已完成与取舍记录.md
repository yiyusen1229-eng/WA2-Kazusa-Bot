### #19 演出 / 切片规则配置化（2026-11-05）

**结论**：做完。每角色可以带两个配置文件，**只写覆盖值**，缺了/写错就用现状默认——
不配的时候行为和以前完全一样。

**依据**

  逐字段校验（数字夹边界、类型不对回默认、未知键忽略、坏 JSON 全默认），每条问题给一条 warning，
  并且同一问题只记一次日志。**不缓存结果**——改完文件下一轮就生效。
- 文件（都在角色文件夹里）：
  - `performance.json`：`fade_ms`（200~300）、`mood_to_emotion`、`outfit_by_scene`。
  - `persona_slices.json`：`story_k`、`story_max_chars`、`worldbook_entries`、`worldbook_chars`、
    `memory_max_chars`。
- 后端接入：`api_chat` 的世界书条数/字数、原作检索 k/字数、常驻记忆上限全部改读 `perfcfg.slices()`；
  `/api/performance` 交给前端；`params.py` 里 5 个参数的「来源」注明可被角色配置覆盖。
- 前端接入：`ui/wt-perfcfg.js`（`WA2.perfCfg`）启动与切角色各拉一次；
  `wt-fade` 的时长三级来源（内置 240 → `fade_ms` → `prefs.xfadeMs`）；
  `wt-sprite` 的情绪/场景映射按「内置表 + 覆盖表」合并。

**代价 / 边界**
- 映射表只做「覆盖/追加」，不能删内置项（要删得改代码）。
- 校验是**逐字段**的：一个字段错不影响其它字段；但整份 JSON 语法坏掉就是全默认。
- 前端拿到配置有 1 次 fetch 的延迟：首帧用内置默认，之后才换成角色配置。
- 配置错误只弹一次 toast + 一条 WARN，不弹窗打断。

**验证**：`tools/test_perfcfg.py` 44 项（默认值=代码常量 / 覆盖 / 夹取 / 类型 / 未知键 / 坏 JSON /
映射表清洗 / 换角色 / 改文件立刻生效 / 带 BOM）；`tools/test_perfcfg.js` 16 项（拉到之前不复制默认表、
拉到之后生效、warning 只 toast 一次、接口失败保留旧值）；`test_fade.js` 加到 31 项
（`fade_ms` 三级来源 + 夹取 + 抛错回默认）；`run_smoke.py` 27 项全绿（在线接口 8 个）。
真机探针：`fade_ms` 300 生效、场景 → 服装、情绪 → 表情两条映射都生效，`fade_ms: 999`
被夹到 300 并带 warning，无 JS 报错。

### #3 常驻记忆书更新（2026-11-05）

**结论**：做完。常驻记忆书从「一坨静态文本」变成两段：**固定设定**（用户的，程序不动）+
**关系摘要**（关系阶段变化时后台刷一次）。存在角色文件夹的 `memory/standing.json`。

**依据**
- `program/src/standing.py`：
  - `text()`：有 standing.json 就拼「fixed + 【我们之间现在的进展（摘要）】」；
    没有就回落 `char_res.memory_text()` —— **注入行为对老角色完全不变**。
  - `build()`：把 `memory/*.txt` 抄成 fixed（只抄这一次）、调模型写 3~6 行摘要、
    原子写 `{version, fixed, relation_summary, stage, updated_at, source_msgs}`。
  - `note(stage, msgs)`：阶段变了才在**后台线程**刷一次；每个阶段最多一次；
    阶段 1（刚认识）不生成；同一阶段失败过冷却 30 分钟；不阻塞对话。
  - 失败 / 模型返回空 → 保留旧文件、记 WARN，绝不写坏。
- 接入：`api_chat` 把注入源换成 `standing.text()`，一轮结束调 `standing.note(阶段, 历史)`；
  `main` 注入 `_mem_llm`（同一套便宜模型调用，max_tokens=400）；
  `/api/memory` 多返回 `two_part / stage / updated_at / hint`；记忆书界面顶部会显示
  「关系摘要更新于 …」，还没有文件时显示提示。
- 自测：`tools/test_standing.py`（44 项）。

**代价 / 边界**
- 摘要质量取决于模型，写坏了用户可以直接编辑 / 删 `standing.json`（删了立刻回落到老文本）。
- 只在阶段变化（≥2）时生成：一直停在阶段 1 的角色不会有摘要——那时也确实没什么可写。
- 每次生成要一次模型调用（几百 token）；失败冷却 30 分钟，不会每轮都打。
- `fixed` 一旦生成就不再自动更新：用户后来改了 `memory/*.txt`，要同步就删掉 standing.json 重建。

**验证**：`test_standing.py` 44 项全绿（回落 / 两段 / fixed 不被改 / 每阶段一次 / 不阻塞 /
失败保留旧版 / 清理格式 / 坏 json / 没 LLM / 没角色）；真机 `/api/memory` 报
`two_part=false + hint`、`/api/chat` 正常且 `memory_extra=631`（= 老文本长度，回落路径对）。

### #14 像素工具化 + 性能采样（2026-11-05）

**结论**：做完。`界面像素测量方法.md` 里那套手工流程变成了一条命令
（`measure_ui.py`，纯 Pillow，不依赖 numpy）；跑久了会不会涨也有数了
（`logs/perf-<日期>.csv`，每 20 轮一行）。

**依据**
- `program/tools/measure_ui.py`：
  - `profile <原图>`：行剖面中位数压掉文字 → 找周期峰定行距 → 列剖面 50% 交叉点定槽位宽 →
    换算到 800×450 舞台，并检查宽高比是否等于素材宽高比。
  - `verify <截图>`：先裁黑边、缩到 800×450，再用同一套检测器量。
  - `compare <原图> <预览图>`：两张都换算到舞台坐标后给**偏移量**（逐峰中位数）、
    周期比、宽比、宽高比差；任一项 >1% 就算「形变」，退出码 1。
  - 稳健性：先轻度平滑再找峰 + 峰显著性过滤 + 「相邻差值的众数」+ 等差距链；
    凑不出稳定周期时**明说「不是整帧原图 / 不是这个界面」**（`confident=False`），不硬给数字。
- `program/src/perf.py`：`snapshot()` 量内存 / 线程 / 句柄 / GDI·USER 对象 / 字模缓存条数 /
  TTS 缓存文件与体积 / 记忆条目 / 上一轮耗时与 token；`maybe()` 每 N 轮在**后台线程**写一行；
  `WA2_PERF=0` 关掉、`WA2_PERF_EVERY` 改间隔；写文件失败只记 WARN。
- 接入：`api_chat` 一轮结束调 `perf.maybe()`；`diag.snapshot()` 多一个 `perf` 块（调试面板可见）；
  `logpack` 按同一天数清理 `perf-*.csv` 并把它打进诊断包。
- 踩坑：`GetProcessHandleCount` 不设 `argtypes` 时 64 位 HANDLE 会截断成 C int，调用失败但返回 0 ——
  「句柄」那一列会恒为 0。补上后真机 133；自测里加了「Windows 上 > 0」。

**代价 / 边界**
- 采样是「每 N 轮一次」，不是连续采样：短会话不会产生数据，长会话只看到抽样点。
- 句柄 / GDI / 内存都是 **Windows API**；别的平台返回 0（不影响其它列）。
- 「音频句柄」没进 CSV：那是前端 `Audio` 对象，后端看不到；语音状态看调试面板「语音」行。
- 像素工具只认真实整帧截图 + 同尺寸舞台；拼图 / 带黑边 / 非 16:9 会先警告或拒绝给结论。

**验证**：`tools/test_measure_ui.py` 25 项（合成图已知答案：行距 60、首峰 76.8、槽位宽 395、
宽高比 6.583；+2px 平移 → 偏移 +2 且判定「只有平移」；放大 2% → 报形变；带黑边截图裁完数字不变；
噪声图不硬给数）；`tools/test_perf_sample.py` 59 项（字段齐全且是数字、CSV 表头只写一次、
不到间隔不采、关掉不采、目录写不进去也不抛）；`run_smoke.py` 24 项全绿（约 6 秒）。
真机 `profile` 跑 `other/docs/img/存档界面_修复后.jpg`：周期 99.7 图上px → 56.95 舞台px、
槽位宽 390.2、宽高比 6.85（这张是我们的旧渲染，不是原版整帧，数字本身合理）。

### #15 日志诊断包（2026-11-05）

**结论**：做完。日志按天滚动（默认 14 天）；「帮助 → 导出诊断包」打一个**脱敏后**的 zip
（日志 + 配置摘要 + 素材报告 + 版本 + 调试状态），默认**不含对话原文**，要带就显式选「含最近 20 轮」

**依据**
- `program/src/logpack.py`：
  - `prune()`：`app-YYYYMMDD.log` 只留最近 N 天（`WA2_LOG_KEEP_DAYS`，默认 14），
    正在写的那个永不删；崩溃现场（`crash_*.log` / `crash_*_auto.json`）只留最新 10 份。
    启动时由 `main._log_maintenance()` 跑一次。
  - `scrub()`：密钥（`secret.redact`）→ `/api/text` `/api/tts` 的查询串（**对话 / 朗读文本**）
    → 用户目录、盘符绝对路径只留文件名。
  - `bundle()`：zip 里放 `README / version / env / logs/ / asset_report / run_state /
    diag_state / config_summary`，`turns>0` 时才多一份 `conversation.json`。
- `program/src/api_log.py` + `main` 路由：`GET /api/log/bundle?turns=N`（0~200，默认 0）。
- `main._log_request`：`/api/text`、`/api/tts` 的查询串不再写进日志（以前会把整句对话 / 朗读文本写进去）。
- 前端：`帮助` 菜单三档——「导出运行日志（诊断卡死）」（栈快照，原有）/
  「导出诊断包（不含对话）」/「导出诊断包（含最近 20 轮）」（`confirm` 风险提示）。

**代价 / 边界**
- 默认包里只有「非对话」的东西；含对话时必须显式选，README 里也再警告一次。
- 脱敏是**正则级**（密钥形状、敏感接口查询串、用户目录、盘符路径），不是内容识别：
  - 对话里如果出现「像密码的普通词」，不会被认出来（也不该猜）。
  - 包里的模型名、时期、衣服名、世界书条目标题会保留——排查需要，且不算隐私。
- 保留天数与崩溃份数是常量 / 环境变量，不进 `参数与指标.md`（不影响对话行为）。

**验证**：`tools/test_logpack.py` 40 项（脱敏、清理、包结构、默认不含对话、含对话时仍脱敏、
无真 key、无用户目录、README 风险提示）；`run_smoke.py` 在线冒烟里真调一次
`/api/log/bundle` 并校验能打开、有 README，再删掉；真机生成的包里没有 `sk-` 形状的串、
没有 `/api/text?text=`、没有用户目录。

## 换了做法了结

### #1 缓存隔离与淘汰 → 改成「启动全清 + key 带角色」

**结论**：**不按原方案**做 `cache/<角色>/` 分层与 LRU。原方案要解决的问题（切角色串音、硬盘失控）已经用更省事的办法解决。

**实际做法**
- 启动时清空文字渲染缓存、TTS 缓存、记忆运行时（`main.py` 的 `main()` 开头三连）。
- TTS 缓存 key 里带角色 id 与参考音频目录签名（`tts_client._char_voice_sig`），换角色必失效。

**解决了的**
- 切角色不会听到 / 看到上一个角色的内容（这是原方案最在意的点）。
- 硬盘不会越用越大。

**代价**
- 每次开程序，第一句语音都要重新合成；第一次进游戏的字模要重渲染。**这是有意的取舍，不是 bug。**

**还没做的**（写在路线图 #1 里）：跨启动保留、按角色分层、体积上限。只有「每次启动重合成」真的变成问题时才值得回头做。
