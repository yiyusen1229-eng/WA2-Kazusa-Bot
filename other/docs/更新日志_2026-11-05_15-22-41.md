## 做了什么

常驻记忆书从「一坨静态文本」变成两段：

| 段 | 谁写 | 什么时候变 |
|---|---|---|
| `fixed`（固定设定） | 用户的 `memory/*.txt` | 只在首次生成时抄一份，之后程序不动 |
| `relation_summary`（关系摘要） | 程序（模型） | 关系阶段变化时后台刷一次 |

存放在 `characters/<角色>/memory/standing.json`（**本地数据，不入库**）：

```json
{"version": 1,
 "fixed": "固定设定（从 memory/*.txt 抄来）",
 "relation_summary": "- 已经确认关系\n- 她开始主动约你",
 "stage": 3, "updated_at": "2026-11-05 15:20:00", "source_msgs": 88}
```

### 规则（都写进代码注释和架构文档了）

- **向后兼容**：没有 `standing.json` 或文件坏了 → 回落 `char_res.memory_text()`，
  注入内容和以前**一模一样**（真机验证 `memory_extra=631` = 老文本长度）。
- **每个阶段最多一次**：stage 记在文件里，同阶段直接跳过。
- **阶段 1 不生成**：刚认识没什么进展可写，不白花一次模型调用。
- **失败冷却 30 分钟**：模型超时 / 返回空 → 保留旧文件 + WARN，同一阶段不会每轮都打模型。
- **不阻塞**：刷新在后台线程，`note()` 立刻返回（自测里用 0.4 秒慢模型验证过）。
- **原子写**：先写 `.tmp` 再 `os.replace`，不会留下半截 JSON。

### 接入

- `api_chat`：注入源换成 `standing.text()`；一轮结束调 `standing.note(阶段, 历史)`。
- `main`：注入 `_mem_llm`（同一套便宜调用，max_tokens=400）。
- `/api/memory`：多返回 `two_part / stage / updated_at / hint`。
- 记忆书界面：顶部显示「关系摘要更新于 …」，还没有文件时显示提示。

## 自测

`program/tools/test_standing.py`（44 项）：

- 没有文件 → `load()` None、`text()` 回落 `memory/*.txt`
- 首次刷新 → fixed 抄过来、摘要写进去、stage / updated_at / source_msgs 都对、不留 `.tmp`
- **fixed 是用户的**：用户改过之后，再刷多少次都不覆盖
- 每阶段一次：同阶段 `note()` 返回 False；换阶段才 True，文件真的更新
- 不阻塞：慢模型下 `note()` < 0.2s 返回，后台线程随后完成
- 失败保留旧版：模型抛错 / 返回空 → 文件内容一字不变
- 阶段 1 不生成；失败后同阶段冷却（不再立刻重试），换阶段不受冷却影响
- 模型输出清理：≤6 行、每行 ≤80 字、总共 ≤600 字、统一 `- ` 前缀
- 坏 json → 回落老文本不炸；没有 LLM → 什么都不做；没有角色 → 自动建默认角色不炸

`run_smoke.py` 25 项全绿（约 6.5 秒）。

## 没做 / 边界

- 摘要质量看模型；写坏了用户可直接编辑或删 `standing.json`（删了立刻回落老文本）。
- `fixed` 不会跟着 `memory/*.txt` 自动更新：改了 txt 想重建就删掉 `standing.json`。
- 真窗口里「关系阶段变化 → 摘要真的刷新」没法在自测里端到端跑（要 40 轮对话 + 云端判定）；
  已用单元测试覆盖 `build()` 和 `note()` 两条路径，真机上等自然触发即可。
