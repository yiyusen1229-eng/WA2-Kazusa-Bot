| 10 个槽位 | `sys_01010` 左上格 | 「没有数据 / No Data」状态 |

### 白线延伸的做法

最初的写法是用 CSS 平铺切片延伸，接缝始终对不齐。最终改成**在图片里延伸**：

```
取 sys_03010 的第 48~96 行（PAGE + 白线）
放大 4 倍超采样
用最右端那一列像素向右复制，直到窗口宽度
→ pg_row.png，一张图，没有任何拼接
```

这个思路之后可以复用到所有「需要延长」的 UI 元素上。

## 二、页签三态：全部来自原图

`sys_01021.tga` 640×96 = 10 列 × 3 行。逐行取最亮 10% 像素的颜色来判断用途：

| 行 | 最亮像素 RGB | 用途 |
|---|---|---|
| 行 0 | (182, 250, 251) 青 | 当前页（亮） |
| 行 1 | (183, 189, 104) 黄 | **悬停** |
| 行 2 | (101, 135, 141) 暗青 | 常态 |

**关键认知**：黄色是素材里本来就有的，不需要用 CSS 滤镜染色。之前用 `sepia/hue-rotate` 模拟是错的。

### 实现方式

尝试过两种，最终用第二种：

1. ❌ 一个容器 + 10 个热区 + `background-position` 取图 —— 界面隐藏时 `offsetWidth = 0`，取图全错
2. ✅ 预生成图片：`tabs_p1..10`（当前页亮）+ `tab_hover_1..10`（单格黄），用两张 `<img>` 叠加

## 三、踩的坑（这次问题特别多）

### 3.1 一个多余的 `</div>` 毁掉整个布局

清空存档界面时，脚本多插入了一个 `</div>`：

```html
<div class="uiFoot">…</div>
</div>   ← 关闭 #saveScreen
</div>   ← 多余，把外层容器提前关闭
```

后果：

- 系统设置界面出现黑边
- 全屏错位
- 主菜单一度也有黑边

而存档界面本身看着正常（它的元素都在断裂点之前），所以一开始没往结构上想。

**教训**：改动 HTML 后必须做 `<div>` 配平检查。现在已写进构建脚本。

### 3.2 错误的「修复」放大问题

在不知道根因是结构断裂的情况下，我加了 `fitstage.js` 做舞台缩放，结果让黑边更明显。

**教训**：现象出现后先确认「结构/数据是否正确」，再考虑「逻辑是否需要补」。

### 3.3 换算错了一次

槽位尺寸第一次算错，原因是：数字是从 **1708 宽的预览图**上读的，却用了 **2730 原生宽**的换算系数（÷3.4125）。

正确系数：`800 / 1708 = 0.4684`。

**教训**：量之前先确认「这张图多宽」，并把系数写在代码注释里。

### 3.4 改了看不到效果

有几次用户反馈「根本没变」，实际是：

- 打包时间晚于用户截图时间（用户看的是旧包）
- 或者 CSS 里残留了 `display: none` 把新规则盖住

现在每次改完都会检查：目标规则是否存在、是否有重复/冲突、打包时间是否最新。

## 五、方法论总结

这一轮最大的收获不是代码，是几条流程：

1. **素材优先**：能直接从原图取的就不要用 CSS 滤镜模拟
2. **自己先看到**：用浏览器打开测试页截图，比让用户反复试快得多（页签的问题就是这样定位的）
3. **一次只改一个量**：位置、尺寸、层级分开调，改完立刻验证
4. **结构先于样式**：HTML 配平、元素是否存在，比 CSS 数值更基础
