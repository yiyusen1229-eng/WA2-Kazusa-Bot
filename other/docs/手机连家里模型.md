# 手机在外网连家里电脑上的模型（语音 / 本地对话）

> 场景：人在外面，手机上的程序要用**家里 PC** 跑着的 GPT-SoVITS（语音）和/或 Ollama（本地模型）。
> 本文只讲连通性与安全，代码侧已经支持（`tts_client.endpoint()` / `is_remote()`）。
>
> 一句话：**做的不是「把模型搬到手机」，是「让手机能访问家里那台机器」。**

## 0. 先分清三样东西在哪

| 东西 | 在哪儿跑 | 外网要访问吗 |
|---|---|---|
| 程序后端（`main.py`，HTTP 8771） | 手机（Termux）或 PC | 看你选哪种玩法 |
| 对话模型 | 云端（DeepSeek） | 不用，手机直连云端 |
| **语音模型 GPT-SoVITS** | **家里 PC**（手机跑不动） | **要** |
| 本地对话模型 Ollama | 家里 PC | 想用本地模型才要 |

两种玩法：

- **玩法 A（省事）**：PC 上照常开程序，手机浏览器打开 PC 的地址。
  → 只需要暴露 **8771** 一个端口，语音/模型都在 PC 本机跑，等于手机当屏幕。
- **玩法 B（手机本地渲染）**：手机跑程序（Termux），语音/模型指向 PC。
  → 需要暴露 **9880（语音）**，要用本地对话模型再加 **11434**。

两种都要先解决同一件事：**外网怎么找到你家 PC**。

## 1. 让外网能到 PC：三种方案

### 方案一：Tailscale（推荐）

- 原理：PC 和手机都装 Tailscale，登录同一个账号，两边各得一个 `100.x.y.z` 的虚拟内网地址；
  走的是加密的点对点隧道，**不用公网 IP、不用在路由器上开端口**。
- 优点：设备级身份认证（别的设备看不到你）、NAT 后面也能用、手机在 4G 下照样通。
- 做法：
  1. PC 装 Tailscale 并登录（托盘图标显示 Connected）
  2. 手机装 Tailscale App 并登录同一账号
  3. 在 Tailscale 后台（或 PC 图标菜单）看到 PC 的 `100.x.y.z`
  4. 手机上的程序/K 浏览器就用这个地址访问，例如 `http://100.x.y.z:9880`

### 方案二：Cloudflare Tunnel

- 原理：PC 上跑 `cloudflared`，它主动往外连，给你一个公网 HTTPS 域名。
- 优点：手机**不用装任何客户端**；能配 Cloudflare Access 做登录校验。
- 缺点：要有个域名托管在 Cloudflare；第一次配置比 Tailscale 麻烦。

### 方案三：路由器端口映射 / 公网 IP

- **不推荐**。原因：GPT-SoVITS 的 `api_v2` **默认没有任何鉴权**，谁扫到这个端口都能用你的
  声音模型合成语音、消耗你的算力。真要开，必须前面加一层带 Basic Auth 的反向代理。

## 2. PC 侧：让语音服务听局域网

默认它只听本机（安全）。要让别的设备能连，启动时指定监听地址：

```powershell
# 在启动程序的同一个终端里先设环境变量（只影响这一次）
$env:WA2_TTS_BIND = "0.0.0.0"
.\和纱.exe            # 或 python main.py
```

程序会用 `bind_host()`（`tts_client.py`）把它传给 GPT-SoVITS 的 `api_v2.py -a 0.0.0.0`。

然后放行防火墙（**只对本机网络/Tailscale 网段**，别对所有人开放）：

```powershell
New-NetFirewallRule -DisplayName "WA2 语音 9880" -Direction Inbound -Protocol TCP `
  -LocalPort 9880 -Action Allow
```

验证（在手机或另一台机器上）：

```
浏览器打开 http://<PC的地址>:9880/      → 应看到 Swagger/接口文档
```

## 3. 手机侧：把语音端点填进去

程序里「特别模式 → 模型管理 → 语音」那一栏：

| 字段 | 填什么 |
|---|---|
| 端点 | `http://100.x.y.z:9880`（Tailscale 地址）或 `http://192.168.1.5:9880`（同局域网） |
| 模型 | 不用填（语音这块只用到端点） |

点「连接」按钮 → 它真的会去探这个地址（`main.probe_endpoint(sec="voice")` 会依次试
`/docs`、`/`、`/openapi.json`…），成功会变绿。这一步**不依赖本机有没有装 GPT-SoVITS**：
`tts_client.available()` 在远程模式下只做 HTTP 探活。

## 4. 代码侧改了哪三处（已改）

| 原来 | 现在 |
|---|---|
| `_wait_ready()` / `start()` 用写死的 `(HOST, PORT)` 探活 | 用 `endpoint()`（从 `URL` 解析），配了远程地址就探远程 |
| `available()` 只看本机权重/`python.exe` | 远程模式只做 HTTP 探活（本机没权重也算可用） |
| 启动参数 `-a HOST` 只能听本机 | `-a bind_host()`，默认仍 127.0.0.1，`WA2_TTS_BIND=0.0.0.0` 才放开 |

自测：`program/tools/test_tts_remote.py`（14 项）——端点解析、远程判定、
「假 host 探活必须失败」（证明没再偷偷摸本机）、远程可用性、复用已有服务不误启动。

## 5. 出门前检查清单

- [ ] 家里 PC **不睡眠**（电源计划改成「从不睡眠」，或者干脆关机也行——那就没语音了）
- [ ] Tailscale 在 PC 上保持登录、手机能看到 PC 的 `100.x` 地址
- [ ] PC 上程序用 `WA2_TTS_BIND=0.0.0.0` 起过（否则语音只在本机）
- [ ] 手机上语音端点填的是 Tailscale 地址，点「连接」是绿的
- [ ] 出门前在手机 4G 下试一次（不要在同一个 WiFi 下试，那样测不出 NAT）

## 6. 已知限制

- **延迟**：语音要过网络，第一次合成会慢（几秒）。同一句话第二次走缓存
  （key = 文本 + 语种 + 情绪 + 参考音频版本），所以重复的台词是瞬时的。
- **PC 必须在线**：关机就没有语音和本地模型；云端对话不受影响。
- **流量**：每条语音是几十 KB 到几百 KB 的 wav/mp3，按句数估算即可。
- **安全**：Tailscale / Cloudflare 都带认证；**不要**把 9880 直接映射到公网。
