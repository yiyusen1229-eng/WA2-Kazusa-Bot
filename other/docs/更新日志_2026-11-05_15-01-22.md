# 更新日志 2026-11-05（#15 日志诊断包）

> 本轮只做**本地提交**：不 push、不改版本号、不生成补丁。角色内容不碰。

## 做了什么

三件事：日志按天滚动、导出前统一脱敏、真的能导出一个诊断包。

### 1. 日志按天滚动（默认 14 天）

- `program/src/logpack.py`：`prune()` 只留最近 N 天的 `app-YYYYMMDD.log`
  （`WA2_LOG_KEEP_DAYS`，默认 14）；**正在写的那个永不删**（哪怕日期很旧）；
  崩溃现场（`crash_*.log` / `crash_*_auto.json`）只留最新 10 份。
- `main._log_maintenance()`：启动时跑一次（两处入口都加了），删了多少写一行日志。

### 2. 脱敏：导出前统一过一遍

`logpack.scrub()` 按顺序做：

| 抹什么 | 怎么抹 | 为什么 |
|---|---|---|
| 密钥 | `secret.redact()`（`sk-…` / `Bearer …` / `api_key: …`） | 老需求，这里复用 |
| 对话 / 朗读文本 | `/api/text?…` `/api/tts?…` → `/api/text?<已隐藏>` | **这两个接口的查询串本身就是台词** |
| 用户目录 | `C:\Users\<名>\…` → `%USERPROFILE%` | 免得带出 Windows 用户名 |
| 其它绝对路径 | `D:\games\wa2\x.log` → `…\x.log` | 文件名留着排查，路径不暴露 |

顺手把日志源头也改了：`main._log_request` 现在**不记录** `/api/text`、`/api/tts` 的查询串。

### 3. 诊断包（`/api/log/bundle` + 帮助菜单）

zip 内容：`README.txt`、`version.json`、`env.txt`（`WA2_*` 变量，值脱敏）、
`logs/`（最近 N 天 + 最近 3 份崩溃现场）、`asset_report.json`、`run_state.json`、
`diag_state.json`、`config_summary.json`（key 只有掩码）。

- `GET /api/log/bundle?turns=N`（0~200，默认 0）。`turns>0` 才多一份 `conversation.json`，
  内容是当前角色自动存档的最后 N 轮，**每段仍然脱敏**。
- 菜单「帮助」三档：「导出运行日志（诊断卡死）」（原来的栈快照）、
  「导出诊断包（不含对话）」、「导出诊断包（含最近 20 轮）」（先 `confirm` 警告）。
- README 里写清楚包含什么、脱敏做了什么；含对话时再警告一次「发给别人前先自己看」。

## 自测

新增 `program/tools/test_logpack.py`（40 项）：

- 脱敏：真 key、查询串、Windows / Linux 用户目录、其它盘符路径；普通文本不动；None 不炸
- 清理：过期删、近期留、dry-run 不删、**正在写的不删**、崩溃现场只留 10 份
- 诊断包：结构齐全、默认不含 `conversation.json`、`turns=2` 只带 4 条、
  包内没有真 key（掩码 `sk-****abcd` 不算）、没有用户目录、没有查询串
- 空目录也能出包（README + 版本），`turns` 上限夹到 200

`run_smoke.py` 的在线冒烟也加了一项：真调一次 `/api/log/bundle` → 校验能打开、有 README → 删掉。

## 修的一处隐患

`logpack` 一开始对**已经 dumps 好的 JSON** 做正则脱敏，结果把 `D:\\games` 这种转义改坏，
`conversation.json` 直接变成非法 JSON。改成**先结构脱敏再 dumps**
（`_scrub_obj()` 递归处理 dict / list 的字符串值）。这是测试抓出来的。

## 没做 / 边界

- 脱敏是**正则级**，不是内容识别：对话里「像密码的普通词」不会被猜出来；
  模型名 / 时期 / 衣服名 / 世界书条目标题会保留（排查需要）。
- 保留天数、崩溃份数是常量 / 环境变量，没有进 `参数与指标.md`（不影响对话行为）。
- 导出的是 zip 文件路径，界面只弹路径，没有做「一键打开所在文件夹」
  （要开就用系统文件管理器；`/api/special/open` 只认角色文件夹）。
