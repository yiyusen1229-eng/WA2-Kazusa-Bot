## 一、这次改了什么

1. **场景 / 服装移到顶部菜单**
   - 顶部「场景 / 服装」：场景地点、场景时段、服装、时期、锁定场景/服装。
   - 手动切换写入当前存档；锁定后模型标签不覆盖手动选择。
   - 不再使用游戏内场景/服装面板，也不再需要工具栏「景」入口。

2. **IC / CC / CODA 时期系统**
   - 当前衣服 → 时期；顶部菜单可手动锁时期。
   - 人设按 `persona_ic.txt` / `persona_cc.txt` / `persona_coda.txt` 追加时期补丁，
     `【当前时期】` 优先级最高。
   - 世界书条目支持 `period` 字段：`ic` / `cc` / `coda` / `all`，每轮只注入当前时期 + 通用条目。

3. **角色切换改成列表**
   - 特别模式 → 配置角色 → 切换角色，不再弹系统文件夹选择框。
   - 直接列出现有角色，当前角色高亮，点另一个一键切换。
   - 切换后刷新名字、立绘索引、人设/世界书、语音配置与存档目录。

4. **按角色隔离存档**
   - 存档目录改为 `characters/<角色>/sessions/`。
   - 切换角色不会读到另一个角色的自动存档 / 手动存档。

5. **按角色语音配置**
   - `tts_client.py` 从 `characters/<角色>/tts.json` 读 `gpt` / `sovits` 权重；
     同一 GPT-SoVITS 进程内切权重，不重启服务。
   - 没有 `tts.json` 时保持原行为。

6. **读音 / 开场白配置化**
   - `tts_client.py` 从 `characters/<角色>/pronunciation.json` 读名字 → 假名映射，
     送 TTS 前替换，界面文字不变。
   - `/api/character/opening` 从 `characters/<角色>/opening.json` 读开场白
     `{zh, ja, emotion}`；前端首句语音走这份配置。
   - 代码里不写死具体角色名 / 权重路径。

7. **启动与首句语音**
   - 启动默认全屏（按 `prefs.json` 的 `winMode`）。
   - 「动作」开关默认开。
   - 新游戏第一句 / 继续游戏最后一句自动配音；TTS 冷启动最多等 60 秒。

8. **人设文件识别修复**
   - `char_res.prompt_path()` 优先 `persona_core.txt` / `persona.txt` / `base.txt`，
     不再按目录字母序把 `persona_cc.txt` 当成整份人设。

## 八、角色切换面板 UI 修正（2026-11-03 下午）

用户反馈：角色多了列表被压扁、标题压在框线上。改为：

- **标题移到框外**（框上方，居中）
- **列表可滚动**：条目固定 30px 高（`flex: 0 0 auto`），装不下就滚，不再压缩
- 滚动条用回想同款（5px、青色半透明滑杆）
- **取消按钮移到框外**（框下方），不再压住面板花纹
- 面板高度自适应：少角色时 176px，多角色最高 64vh，列表内部滚动

实测（真实 WebView2）：2 个角色时紧凑无滚动；注入 13 个条目时 `itemHeight=30.4`、
`scrollHeight 442 > clientHeight 232`（可滚）、标题在框外、无 JS 报错。
### 八、补记：结束游戏不退出 + 底框变形（同一轮修）

| 问题 | 原因 | 处理 |
|---|---|---|
| 点「结束游戏」不退出 | 只调了裸 `window.close()`，WebView2/pywebview 里不保证生效 | 改成 `quitGame()`：先 confirm，再依次走 **pywebview 桥接 `api.win("close")` → HTTP `/api/window?action=close` → `window.close()`**；confirm 不可用（返回 undefined）时也照关，只有明确点“取消”才不关 |
| 角色面板底框被压扁 | `sys_00100.png`（544x216）被 `background-size:100% 100%` 纵向拉伸，边框和雪花花纹变形 | 不再用位图做底框，改成 **CSS 画**（渐变 + 青色描边 + 外发光 + 圆角），高度多少都不变形；条目底板仍用原素材 |

验证：
- `__quitGame` 三条分支：confirm=undefined → `true`（照关）、confirm=false → `false`（不关）、confirm=true → `true`
- 服务端日志出现 `窗口控制: action=close`，说明 HTTP 关闭链路真的走到了（真实窗口下日志里是 `window=有`）
- 面板 2 个角色时 120px 紧凑；注入 13 个条目时列表滚动（scrollHeight 442 > clientHeight 232）、条目 30px 不被压扁、底框无变形
> 更正：压扁的是**条目底板** `sys_00110.png`（480x112 → 拉到 300x30），不是面板底框。
> 现在条目也改成 CSS 画的条子（渐变 + 高光 + 描边 + 发光），不再用位图拉伸；
> 面板底框（`sys_00100`）同样是 CSS 画的。两个位图都被 `sys_00110` 撑变形的问题一起解决了。
> 再更正：面板和条目**都改回用原素材**（`sys_00100` / `sys_00110`），
> 但改成 **CSS 九宫格（`border-image` 切片）**：四角保持等比、只拉伸中间段，
> 所以既保留了原版边框花纹，又不会被压扁。条目高度 44px（原来 30px 太矮，硬拉才会变形），
> 面板最少 150px、最多 64vh，角色多了列表内部滚动。
> 最终版：底框和条目都**回到原素材、按原比例等比缩放**（`aspect-ratio` 锁定 544:216 / 480:112，
> 图片 `100% 100%` 铺在同比例容器里 = 等比缩放），自画的渐变/色块全部删掉。
> 代价：底框比例固定，装不下就列表内部滚动（面板 520x206，一屏约 2 个角色）。
> 最终尺寸（按用户要求）：底框缩到 **400x159**（保持 544:216 原比例，等比缩放）；
> 条目缩到 **300x30**，再用**九宫格**把中间横向拉长（四角等比，不压扁）。
> 一屏能显示 3 行；少角色时列表垂直居中（`justify-content: safe center`），多角色时滚动。
