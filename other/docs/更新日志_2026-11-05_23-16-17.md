## 补记（23:30，用户看着实机提的两点）

看真机后用户提了两条，都验过了：

**1. 「选中的时候雪花没有亮」—— 雪花层也是加法，不是普通叠上去。**
雪花贴图（`sys_00200` 段3）芯色是 **(149,193,227)**；原版常态那条雪花最亮处实测 **R = 159**，
正好 = 149 + 条身底色 ~10。用普通 alpha 盖上去只能得到 ≤149，所以发灰。
改成 `.choiceSnow { mix-blend-mode: plus-lighter }` 之后：

| 雪花最亮处 | 原版 | 改前 | 改后 |
|---|---|---|---|
| 常态那条 | (159,253,254) | (150,186,220) | (184,254,254) |
| 悬停那条 | (172,254,254) | (125,206,240) | (230,254,254) |

（改后的绝对值比原版高，是因为测试场景的背景是**明亮的教室**，加法会把背景一起抬起来；
换成原版那种暗背景就是 159。关键是指标对上了：雪花跟着条身一起变亮。）

**2. 「选择框出现了很明显的分界线框线」—— 是输入栏的边框，不是选项条。**
`#inputBar` 的青色边框正好横穿选项条那一行（x 512~792 / y 208~273 和第一条选项重叠），
在实机上就是一条笔直的亮线切过选择框。现在选择分支打开时给 `body` 加 `choiceOpen`，
把 `#inputBar` 的 `opacity` 收到 0（选择完 / Esc 关闭时恢复）。
另外把条子放在纯黑上单独截图验过：边缘是 9~19px 的平滑渐变，**没有矩形硬边**。

`?v=` 从 `202611052330` 提到 `202611052330b`。

**3. 「亮起来的时候有明显黑边」—— 是我自己加的 `filter: drop-shadow()` 辉光。**
原版边缘那点"发光"就是贴图自己的 alpha 坡（实测 50% 点外侧 5px 内回到背景值），
并没有额外 bloom；我为了"像发光的"给它加了一层 `drop-shadow`，结果这层滤镜把条子的
**软边压暗了**。同一个场景、只切这一条属性各截一张逐像素比：

| 位置（条子上沿外侧） | 有 drop-shadow | 去掉后 | 差 |
|---|---|---|---|
| y=204 | (212,226,239) | (225,232,238) | R −13 |
| y=206 | (140,167,196) | (155,172,196) | R −15 |
| y=207 | (84,118,163) | (103,126,165) | R −19 |

条子内部倒是变亮了（+10~20），于是内外一对比就是一圈黑边。已删掉这条 filter，
去掉后的截图与"从一开始就不加滤镜"的那张差 ≤2 级。`?v=` 提到 `202611052330c`。

**4.（23:55 补）「选中时那圈框线」的**真正**原因：不再实时叠加，改成素材阶段烘好。**
上一轮把悬停做成「段1 + 段2 用 `plus-lighter` 实时相加」。算式本身没错（原版像素确实是相加），
但**层叠上下文**让它在边缘翻车：选项层带 `z-index: 70`，是独立的层叠上下文，
`plus-lighter` 能混合到的背景只有**条子自己**、不含背后的 CG；而它算的是
`α出 = α源 + α底`（夹到 1）——条子软边那几行 α 本来就小，一夹满整块就变**不透明**，
CG 被顶掉，于是出现一圈黑边：

| 同一场景「有高亮层」「没有高亮层」逐像素差 | 亮度差 |
|---|---|
| y=206（上沿软边） | 中位 **−34**，最暗 −49 |
| y=208（上沿软边） | 中位 **−75**，最暗 **−110** |
| y=222（条身中段） | 中位 **+29** |
| y=228（条身下部） | 中位 **+41** |
| y=234（下沿软边） | 中位 **−28**，最暗 −57 |

（内亮、两边暗 = 一条亮带被两圈黑边夹着，玩家看到的就是「框线」。）

改法：`tools/make_choice_assets.py` 里新增 `bake_hover()`，把段1、段2 按
`C' = (C0*α0 + C1*α1) / α0`（逐通道夹 255）烘成一张 `bar_on.png`，**alpha 直接取段1 的**。
这样悬停只是换图，两张图的 alpha 逐像素相同（脚本里断言过），轮廓一模一样，
结构上不可能再接出边；亮度仍然等于真加法。

改完复测（同一场景「悬停」「不悬停」逐像素差）：**全条区域最小差值 −1.0（只剩噪声）**，
每行中位都是 0 → +75 → 0，只有亮、没有暗。雪花层继续用 `plus-lighter`
（只盖在条子上、面积小，实测只影响雪花抗锯齿边几十个像素）。

## 怎么量出来的（可复现）

参考图：`program/work_scratch/orig_game.jpg`（原版整帧 2730×1536，两条选项）。

1. **缩放系数**：拿 `sys_00200` 段3 的雪花当模板做归一化互相关，在 800×450 上搜尺度，
   命中 **s = 0.625**（= 800/1280，就是整套 UI 素材的固定缩放）。
   → 784×0.625 = **490.0**、72×0.625 = **45.0**，条子比贴图一模一样是 10.9:1。
   上一版把 490 留下、把高写成 22，其实已经把答案量出来了，只是竖着又压了一次。
2. **位置**：两朵雪花的花心相距 **392.5**（贴图里 628×0.625 = 392.5，完全吻合），
   由此反推条子左端 x = **154.7**（正好水平居中）；雪花模板在 y=**148** / y=**200** 命中，
   行距 **52**。
3. **悬停态是加法**：原版悬停那条的像素 = 段1 + 段2 逐通道相加。
   y=214 处 段1(11,91,126)+段2(10,58,123) = (21,149,249)，原版读数 **(41,159,255)**；
   底部 段1(27,153,174)+段2(20,103,136) = (47,256,255)，原版 **(66,245,254)**。
   → CSS 用 `mix-blend-mode: plus-lighter` 叠一层，不再换 `background-image`。
4. **字**：原版字身格 32px（补丁字模 FONT_OCCUPATION）× 0.625 = **20px**，
   全角步进 28×0.625 = **17.5px/字**（原版「把脸背过去」5 字跨 85px，吻合）。
   编号和正文是**同一张字模**（原版就是同字号全角步进，不是另找的数字图），
   所以现在是 `"1." + 选项` 一次渲染，悬停再渲染一张金色的，两层交叉淡入。

## 还留着的两件小事

1. **条宽没法自动判**：右端那一段被右雪花压着（雪花在条内 x 416~452），亮度剖面会先判成
   「条子结束」，量出来短 50px。所以检测器只打印宽度、不做门限；宽度 490 由雪花互相关
   （花心距 392.5）和「素材贴回原版整帧，边沿/雪花/白牌全对上」两处独立证据钉住。
2. **`plus-lighter` 要 Chromium 111+**：实测这台机器的 WebView2 支持；不支持时退化成
   普通覆盖（悬停偏暗，不会坏）。
