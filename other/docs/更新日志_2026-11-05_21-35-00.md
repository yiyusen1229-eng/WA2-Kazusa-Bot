# 更新日志 2026-11-05 21-35-00 · 「素材已更新」一直弹

> 用户问：这个提示的推送机制是什么，为什么一直弹。
> 结论：不是推送，是**轮询**；一直弹是因为把「运行时数据」也算进了素材签名。

## 提示是怎么来的（机制）

```
后端 hotreload 线程（每 2 秒）
  → 扫两个根目录：assets（素材）、当前角色目录
  → 签名 = (文件数, 最大 mtime, 总字节)
  → 签名变了、且连续 0.8 秒不再变（SETTLE，防止加载到半张图）
  → gen += 1，清字模缓存 / 立绘索引 / 素材报告，写一行 ASSET 日志

前端 wt-hotreload.js（每 4 秒）
  → GET /api/hotreload，比对 gen
  → 变了就：assetsVer+1（图片 URL 绕过缓存）、重拉立绘索引、重画背景、弹「素材已更新」
```

没有 WebSocket / 推送，纯粹是「前端定时问、后端比对签名」——所以才会「一直在问」。

## 为什么一直弹

角色目录里除了真正的素材（`portrait/`、`voice/`、`prompt/`、`worldbook/`），还有**运行时数据**：

| 目录 | 什么时候变 |
|---|---|
| `sessions/auto.json`、`sessions/N.json` | 每次对话自动存档、存读档、缩略图 |
| `memory/standing.json` | 关系阶段变化时刷新关系摘要 |

这些一变，签名就变 → gen+1 → 前端弹提示。聊天时自动存档很频繁，于是「素材已更新」几秒一次。
实测复现：往 `sessions/auto.json` 追加一个字节，gen 立刻 0 → 1。

## 修法（两层）

1. **后端不把运行时数据算进签名**：`hotreload.SKIP_DIRS = {sessions, cache, _deleted, logs,
   work_scratch, tmp, __pycache__, .git}`，`SKIP_FILES = {standing.json}`。
   实测：写 `sessions/*`、`memory/standing.json` **不再触发**；写 `portrait/`、`prompt/`、
   `worldbook/`、`voice/` 仍然触发（这些才是真素材）。
2. **前端提示节流**：即使素材被连续改动，提示最多 **15 秒一次**（刷新照做，只是不刷屏）。

## 验证

- `test_hotreload.py` 27 → **30 项**：新增「写自动存档/关系摘要不算素材变了」「写立绘仍然算」
  「跳过名单里有 sessions/cache」
- 真机探针（起后端、逐个写目录）确认：`sessions` ×2、`standing.json` 不触发；其余 4 个触发
- `run_smoke.py` 36 项全绿

## 边界

- 用户**想**让新素材生效时，往 `portrait/`、`voice/` 里放文件仍然会立刻热重载；放完等 2~4 秒即可。
- `prompt/`、`worldbook/` 改动也会触发（下一轮对话本来就会重新读，触发只是让立绘索引也刷一下）。
- 已经开着的旧实例不会自动获得这个修复——要重开程序（或等下一版一键更新）。
