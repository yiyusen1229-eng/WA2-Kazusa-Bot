## 五、卡住的地方（下一轮从这里接）

1. **条的体色**：原版条身是**半透明**的（背景亮就发白、背景暗就发蓝）。
   我给的 `.94` 深蓝渐变偏「实心」，实机观感与原版不像。
   → 需要决定：要不要半透明？用多少 alpha？**建议先问用户**，或直接量原版条的同一位置在
   亮/暗背景下的颜色差来反推 alpha。
2. **几何**：现在用 490×22、上沿 176、行距 29、左端 163、字 11（读数来源：2730 整帧 ×0.29304，
   亮度跳变找边）。这些数**没有在实机上复量过**，很可能还要 ±2px。
3. **两端雪花**：现在从 `sys_00200` 段3 裁成 `snow_l/snow_r` 单独画（30×30，会溢出条外）。
   原版雪花的确比条子高，但**具体多大、离端头多远没有量**。
4. **三段拉伸**：`.choiceBg` 用 `border-image: url(bar_off.png) 0 96 fill / 0 7px stretch`。
   这是为了不把雪花压扁（素材 784×72=10.9:1，条子 490×22=22.3:1）。左右 96px 这个 slice
   值也是估的，应该按「雪花宽度」量出来。

## 七、别再犯的错（我这一轮踩的，逐条记下）

1. **不要凭感觉估尺寸**。我一开始直接写 520×34，用户一眼看出不像。
2. **`sys_00200` 不是一张整条**：三段分别是「常态高光 / 悬停高光 / 两端雪花」，
   条身填充是引擎顶点色染的，贴图里没有。所以必须「渐变打底 + 贴图叠层」。
3. **素材和成品的宽高比不等时，必须三段拉伸**（否则雪花被压扁）。用 `border-image` 或三个 div。
4. **小标签在 `sys_00011` 图集里**（约 (218,63)~(236,96)），不是 `sys_00110`
   （`sys_00110` 是 480×112 的带雪花暗纹蓝板，不是标签）。别再搞错。
5. **`系统设置` 打开的是 `opt.js` 的 OPTION 界面，那三页是烤死的图，塞不进原生控件**；
   要加设置项就放标题栏菜单（`menubar.js`），或另做一层浮层。
6. **选项文字会被 `uitext.js` 的 MutationObserver 自动烤成字模图片**，
   探针要读 `data-uitxt`，读 `textContent` 永远是空的。
7. **`ui_probe.py` 的截图是整窗（3200×1800）**，不是 800×450 舞台；要按舞台量必须自己换算，
   或者用文档 Step 7 的 iframe 办法。
8. 预览页放在 `build_env/ui2/` 里会被 `run_dev.py --sync-only` **清掉**（ui2 是同步生成的），
   要临时预览就先同步、再放进去、再截图，别指望它留到下一次。
