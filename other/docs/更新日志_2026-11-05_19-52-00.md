# 更新日志 2026-11-05 19-52-00

> 主题：**翻译质量**——人名译错、中→日说敬语、云端偶尔空回复。
> 结论：谷歌免费端点不可用（实测 429），改成「云端优先 + 本地兜底 + 术语表」。
> 范围：新增 `program/src/translate.py` + `tools/test_translate.py`，改 `main.translate_ja`、
> `api_chat` 的字幕路径；新增角色级 `translation_glossary.json`（本地数据，不入库）。

## 一、先说谷歌为什么没接上

| 试法 | 结果 |
|---|---|
| `translate.googleapis.com/translate_a/single?client=gtx` | **HTTP 429 Too Many Requests**（两次，带 UA 也一样） |
| 官方 Cloud Translation API | 需要 GCP 计费账号 + key，不是「接上就能用」 |

所以「直接外接谷歌」这条路现在走不通。改用**已经配好的云端模型**（`deepseek-flash`）做翻译，
中文方向上质量明显更好，而且不用新建账号。

## 二、实测发现的三个真问题

用今天日志里的真实台词，本地 Hy-MT2 与云端各翻一遍：

| 日文原文 | 本地 Hy-MT2 | 云端 deepseek |
|---|---|---|
| …はるき、起きてるか | …**春树**，你醒了没？ | ……**春树**，你醒着吗 |
| …そうか。じゃあ、また今度だな | ……原来如此。那，下次再谈吧。 | ……这样啊。那就下次吧。 |
| …わかんない。わかんないけど、悪くない | ……不知道。虽然不知道，但也不错。 | ……搞不懂。虽然搞不懂，但也不坏。 |

1. **人名两个引擎都会译错**：`はるき` → 「春树」，正确是「春希」。**换引擎解决不了，必须上术语表。**
2. **中→日 本地模型满口敬语**：「あなたって、本当に……もういい**わ**。雪が降っているから、早く帰り**ましょう**。」
   —— 和纱不会这么说。云端翻出来是「あんたってば、もう……まあいいや、雪だし、早く帰ろうぜ。」，
   口语、有脾气，这才是能配音的句子。
3. **云端小 token 会被 reasoning 吃光**：`max_tokens=150` 时三句里有一句
   `finish_reason=length` + `content=""`（等于翻译失败且没有任何提示）。
   `reasoning_effort=none` + `max_tokens=300` 时：出词 7~9 token、`finish=stop`、都正常。

## 三、改成了什么样

新增 `translate.py` 一层，所有翻译都走它：

```
to_zh() / to_ja()
  → 引擎链：云端优先（有 key）→ 本地 Hy-MT2 → 空串
  → 术语表后处理（translation_glossary.json，长的先替换）
  → 缓存 500 条
```

- `main.translate_ja()`：先走 `translate.to_ja()`，失败才回落到原来的本地/Ollama 老路径。
- `api_chat`：字幕从「只调本地 Hy-MT2」改成 `translate.to_zh()`，
  `action_zh` 同样。
- 引擎选择：`WA2_MT_PROVIDER=cloud|local` → `config.json` 的 `translate.provider` →
  自动（有 key 用云端）。**没有 UI 开关**，要换就改环境变量或配置。

## 四、术语表（这次真正修掉「名字译错」的东西）

`characters/<角色>/translation_glossary.json`：

```json
{"to_zh": {"はるき": "春希", "春树": "春希", "せつな": "雪菜", "かずさ": "和纱",
           "とうま": "冬马", "たけや": "武也", "いお": "依绪", "ちあき": "千晶",
           "おぎそ": "小木曾"}}
```

两种写法都认（`{"to_zh": {...}}` 或扁平 `{"错": "对"}`）；**长键优先**，
所以「春树」不会被「春」先吃掉。

## 五、验证

| 检查 | 结果 |
|---|---|
| `tools/test_translate.py` | **21 项全绿**：术语表（含长键优先）、清洗、云端优先、云端空→回落本地、local 优先、两边失败给空串、缓存、provider 三种来源 |
| `run_smoke.py` | **35 项全绿**（8.2 秒） |
| 真机（build_env + 真 key + 真术语表） | `provider: cloud`；`はるき` → **春希**；中→日「あんたってば、もう……まあいいや、雪だし、早く帰ろうぜ。」 |

## 六、代价 / 边界

- 每条字幕多一次云端请求（约 +0.5~1s，`reply` 和 `action` 各一次），**回复会更晚出现**。
  嫌慢就 `WA2_MT_PROVIDER=local` 退回本地（质量回到原来那样）。
- 术语表目前只做了 `to_zh` 方向；中→日的名字读音仍靠 `pronunciation.json`（点字）。
- 没有 UI 切换、没有术语表编辑界面；术语表要和 `pronunciation.json` 一起维护（一正一反）。
