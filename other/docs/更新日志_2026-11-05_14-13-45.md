# 更新日志 2026-11-05（#13 调试面板补指标）

> 本轮只做**本地提交**：不 push、不改版本号、不生成补丁。角色内容不碰。

## 做了什么

路线图 #13 的缺口一次补齐：面板从「只有时间线」变成「状态 + 时间线」两块。

### 后端：只读账本 + 一个接口

- `program/src/diag.py`（新）：
  - `count(name, n=1)` 计数器（`text.disk` / `text.mem` / `text.render` / `tts.hit` / `tts.render` / `chat.round` / `chat.error`）
  - `note(kind, **kw)` 模块状态（覆盖写）：场景匹配结果、TTS 响度增益
  - `round_record(**kw)` 一轮对话的指标，滚动保留最近 8 轮
  - `snapshot()` 一次打包；`token_est()` 复用 `memory.est_text` 的估算规则
  - 全加锁（HTTP 服务是 `ThreadingHTTPServer`）
- `GET /api/debug/state`（`main.py` 路由 → `diag.snapshot()`）：
  `server`（版本 / 运行时长 / pid / 环境变量是否设了）/ `counters` / `rounds` / `modules`。
- `modules` 六个块：
  | 块 | 内容 |
  |---|---|
  | `memory` | 条目数 / 上限 / 覆盖到第几条 / 打包次数 / 三档预算 |
  | `stage` | 关系阶段 / 每几轮判一次 / 还差几轮 / 后台是否在跑（`persona_stage.debug_state()`，**只读状态文件**） |
  | `tts` | 是否就绪 / 最近一次的 LUFS→目标 与增益 / 响度备忘条数 |
  | `story` | 最近一次检索的命中（出处 / 分数 / 字数，**不含正文**）/ 索引已加载块数 |
  | `scene` | 最近一次 `<scene>` 匹配（id / 地点 / 时段 / 分数） |
  | `cache` | `cache_io.stats()` 的 checked / dropped |

### 记录点（都是加在现有调用后面，不改原逻辑）

- `api_chat.py`：system 六个分段的**字数**（人设 / 常驻记忆 / 世界书 / 对话记忆 / 原作 / 尾约束）、
  估算 token（system / 消息 / few-shot）、耗时、用量、场景、情绪、衣服；错误路径记 `chat.error`。
- `api_text.py`：字模 磁盘命中 / 内存命中 / 实际渲染 三个计数。
- `tts_client.py`：TTS 命中 / 合成 计数；`_record_gain()` 顺手把响度和增益塞进 `note("tts")`。
- `story_rag.py`：`last_hits()`（出处 / 分数 / 字数）、`cached_blocks()`（只报已加载，不触发加载）。
- `persona_stage.py`：`debug_state()`。

### 前端：面板两块

- `ui/debug.js`：`#dbgPanel` 内拆成 `#dbgState`（状态）和 `#dbgFeed`（时间线）。
  - 状态每 1.5 秒轮询 `/api/debug/state`；**面板关着时不发请求**（第一次打开立刻拉一次）。
  - `window.__dbgState()` 可手动刷新；标题栏「调试」打开时也会立刻拉。
  - 前端自己的状态（演出状态机 / 过渡设置 / 音频设备变化次数）直接读内存，不走接口。
- 顺手修：`error` / `unhandledrejection` 监听器在 IIFE 外直接调 `log`（拿不到，一直被 try/catch 吞掉），
  改成 `window.__dbg`——所以 JS 报错现在真的会出现在时间线里。
- `index.html` 里 `debug.js` / `menubar.js` 的 `?v=` bump 到 `202611051409`。

  面板上把两者分两行摆着，方便对照。
- 不记对话正文、不记密钥；要看正文去看回想 / 存档。
