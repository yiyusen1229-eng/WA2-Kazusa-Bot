# 不要动（改之前先读，每条都写着「动了会怎样」）

> 这份清单只收**踩过坑、改错会静默坏掉**的东西。每条的格式：
> **为什么不能动 / 动了会怎样 / 正确改法**。
> 新踩的坑往这里加（`program/tests/cases.md` 记「怎么测」，这里记「为什么碰不得」）。

## 1. 模块身份：`python main.py` 的主模块叫 `__main__`，不叫 `main`

- **为什么**：`main.py` 里的窗口对象、`_API`、各种全局都在**主模块**里。直接跑时
  它的名字是 `__main__`；`import main` 会**再执行一遍**，拿到一份空的。
- **动了会怎样**：窗口按钮（关闭/最小化/全屏）返回 `{"ok": false, "error": "module
  'main' has no attribute '_WINDOW'"}`——HTTP 200、日志干净、界面毫无反应。
- **正确改法**：要取主模块一律走 `winutil._main_module()`（`main` 和 `__main__` 都查）；
  取窗口句柄走 `winutil._win_hwnd()`，别自己 `import main`。
- 自测：`tools/test_window_api.py`

## 2. UI 像素系数 `0.625`（800 / 1280）

- **为什么**：整套原版 UI 素材是 1280×720 设计尺寸，舞台是 800×450，所以**所有素材
  坐标 × 0.625**（`784×72 → 490×45`、`32px 字身格 → 20px`、`28px 步进 → 17.5px`）。
- **动了会怎样**：选项条/菜单/字模整体尺寸错，且是「看着差不多、量起来全偏」的那种错。
- **正确改法**：写死 0.625 的换算，别凭截图目测；改完用 `tools/measure_choice.py`
  对原版整帧做像素回测（容差 2px）。

## 3. 字模图集是「严格格」，别手改 PNG

- **为什么**：`uitext.js` 把中文按 `FONT_OCCUPATION=32`、步进 28 烘成一张图，
  字体图集边界写死；磁盘缓存键含字体与渲染参数。
- **动了会怎样**：字被切一半、串行、或者换字体后旧缓存继续命中（显示上还是旧字形）。
- **正确改法**：换字体或改渲染参数 → 让 `_clear_text_cache()` 清掉磁盘缓存；
  需要新字就重新烘，别在 PNG 上补。自测：`tools/test_uitext*`、`run_smoke` 的静态项。

## 4. `window.__history` 必须是**同一个数组引用**

- **为什么**：回想（`rebuildBacklog`）读 `window.__history`，存档（`sessionSave`）读模块里的
  同一个数组；`applyHistory` 靠 `length = 0` + `push` 原地改，就是为了让所有持有者同步。
- **动了会怎样**：写 `history = []` 只是换了**绑定**——数组还被 `__history` 指着，
  于是「点开始游戏，回想里还是上一局」。更糟：`history` 这名字在浏览器里挂着 History API，
  赋值会把它覆盖成数组。
- **正确改法**：清历史只能调 `WA2.session.clearHistory()`；要清别的残留，
  各回各家（`WA2.mood.reset()` / `WA2.chat.resetPending()` / `turnCount = 0`）。
- 自测：`tools/test_newgame.py`

## 5. `hotreload.SKIP_DIRS`：运行时数据不算「素材变了」

- **为什么**：`sessions/ cache/ logs/ text_cache/` 这些是程序自己聊天时在写的。
  签名里带上它们 → 每来一句新台词就判「素材变了」。
- **动了会怎样**：前端每几秒重画一次背景（画面闪），外加「素材已更新」提示刷屏。
- **正确改法**：新增运行时目录就往 `SKIP_DIRS` 里加；素材本身（立绘/语音/背景）
  仍然要算——`tools/test_hotreload.py` 里有「同一目录放真素材照样触发」的用例。

## 6. 选择条**不能**用 `mix-blend-mode: plus-lighter` 实时叠高亮

- **为什么**：选项层有 `z-index`，是独立层叠上下文，`plus-lighter` 能混合到的背景
  只有条子自己；而它算 `α出 = α源 + α底` 并夹到 1，条子软边那几行一夹满就变不透明、
  背后的 CG 被顶掉。
- **动了会怎样**：选中时出现一圈**黑边/框线**（实测最暗 −110），内亮外暗。
- **正确改法**：在素材阶段把「常态+高亮」按加法烘成一张（`make_choice_assets.bake_hover`），
  悬停只换图；两张图的 alpha 必须逐像素相同，接不出边。

## 7. 条身**不要**加 `filter: drop-shadow()` 做辉光

- **为什么**：滤镜会把条子的 alpha 坡压暗再合成。
- **动了会怎样**：软边外面那几行变暗 5~10 级，也就是「亮起来的时候有一圈黑边」。
- **正确改法**：要辉光就烘进贴图；原版本来也没有额外辉光，边缘衰减就是贴图自己的 alpha 坡。

## 8. `.choiceTxt` 必须显式 `width`

- **为什么**：它是绝对定位容器，里面是绝对定位的 `<img>`；没有宽度时盒模型塌成 0，
  再被 `overflow:hidden` 一裁就什么都没有。
- **动了会怎样**：选项文字「看不见」，但 DOM 里明明有。
- **正确改法**：`width:400px` 明确写死（见 `choice.css` 的注释）。

## 9. 设置的入口是 `window.App`，**没有 `WA2.prefs`**

- **为什么**：`config.js` 只挂了 `window.App.getPrefs / setPref`。
- **动了会怎样**：读不到就一路回落默认值——「设置里改成几都是 2 个分支」就是这么来的。
- **正确改法**：读 `App.getPrefs()`、写 `App.setPref(k, v)`；保留兜底但别指望它。
- 自测：`tools/test_choices_prefs.js`

## 10. 情绪词表：`沉重` 必须在里面，三处要一起改

- **为什么**：模型靠 `<emotion>` 表达语气。词表里没有「沉重」，模型就没法区分
  「争执/说到痛处」和「日常嘴硬」，冰之刃只能被嘴硬触发。
- **动了会怎样**：BGM 只在两首之间跳；立绘表情永远一张。
- **正确改法**：改词表要同时改三处 —— `api_chat.performance_hints`（告诉模型）、
  `wt-sprite.js` 的 `EMO_ALIAS`（表情）、`wt-mood.js` 的 `EMO_BGM`（BGM 槽位）。
- 自测：`tools/test_chat_hints.py`、`tools/test_mood_bgm.js`

## 11. `build_env/` 是**拷贝**，改完 `src/` 必须同步

- **为什么**：`main.py --serve-only` 跑的是 `build_env/` 里的那份 `.py`；`run_dev.py`
  才负责把 `src/` 同步过去。
- **动了会怎样**：改了源码、测出来还是旧行为（我因此白测过三遍）。
- **正确改法**：改完 `src/*.py` → `python tools/run_dev.py --sync-only`；
  前端还要顺带 bump `index.html` 的 `?v=`。

## 12. 存档 `schema_version` 与 `meta`

- **为什么**：`sessions.py` 有版本迁移；`meta` 是自由字典（`bg / outfit / thumb / choice`），
  加键不用升版本。
- **动了会怎样**：改 `messages` 的结构而不升版本 → 老档读进来字段错位；
  升了版本却没写迁移 → 老档读不出来（会提示「存档来自更新版本」）。
- **正确改法**：只加 `meta` 键 → 不用动版本；动 `messages` 或顶层字段 → 升
  `SCHEMA_VERSION` 并在 `_migrate` 里补一条。

## 13. 素材与人设**不进仓库**

- **为什么**：版权红线（规则第 8 条）+ 私人内容（人设/世界书/存档）。
- **动了会怎样**：`git add -A` 会把 `characters/`、`res/assets/`、`config.json`、
  `fewshot.json` 一起提交——里面有你自己的设定、聊天摘要和 API key。
- **正确改法**：这些路径都在 `.gitignore` 里（`program/src/characters/` 也算，
  因为规则是 `characters/`）。提交前 `git status` 看一眼；不确定就
  `git check-ignore -v <路径>`。

## 14. 会话级状态改写前先看归属

- **为什么**：`__lastEmo / __nextScene / __nextOutfit / __lastAction` 归 `wt-chat.js`，
  `window.__history` 归会话模块，`__bgWarned` 归 `game.js`。
- **动了会怎样**：`check_split.py` 会报「同名全局定义」（基线 91 处，涨了就是这次带进来的），
  实际影响是两块代码互相覆盖同一个状态。
- **正确改法**：加 `resetPending()` 这类归属方法，别跨模块直接写别人的全局。
