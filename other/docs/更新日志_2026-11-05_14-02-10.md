## 做了什么

路线图 #7「多模态过渡（剩余部分）」的三件事全部落地。

### 1. 背景 / 立绘双缓冲交叉淡化

- 以前：换背景是「压到 0.25 → 等 260ms → 换图 → 拉回 1」，中间黑一下；立绘是「藏起来 → 180ms → 显示」，同样空一下。
- 现在：新旧两张同时在场，新的淡入、旧的留在底下，200~300ms 化过去。
- `program/src/ui/wt-fade.js`（新，`WA2.fade`）：
  - `crossBg()`：`#bgLayer` / `#bgLayer2` 两层轮换；过渡结束把新图搬回 `#bgLayer`（`settle()`），
    别的代码读 `#bgLayer` 不会读到旧值。两层都带渐隐蒙版，中途不会变亮。
  - `crossSprite()`：`#spriteGhost` 叠在 `#sprite` 上淡入新图，淡完把主图换成同一张、叠层归零。
  - 换图前先 `new Image()` 预载，避免闪出未解码的空白 / 破图。
- `index.html` 加 `#bgLayer2` 与 `wt-fade.js`，`?v=` 统一 bump；`game450.css` 去掉原来 `#bgLayer` 的 .8s CSS 过渡，
  改成 JS 驱动；`game.js` 的 `setBg()` 与 `wt-sprite.js` 的 `setSpriteByScene()` 改为调 `WA2.fade`，
  `wt-fade` 没加载时保留老做法兜底。

### 2. 语音响度归一化（记增益、不改原文件）

- 新 `program/src/audio_gain.py`：BS.1770 近似（K 加权两级 biquad + -70 LUFS 绝对门 + 相对 -10 LU），
  峰值保护（最多推到 -1 dBFS）、增益夹 ±12 dB、短于 400ms 的片段也能量。
- `tts_client.py`：合成完 / 命中缓存时在 `cache/tts/<hash>.wav.gain.json` 记
  `{target, lufs, peak_db, gain_db, applied, bytes, at}`；**wav 一个字节不改**。
- `api_tts.py`：把增益应用到发出去的字节上，响应头带 `X-Voice-Gain-DB`、`X-Voice-Lufs`。
- 只认 16bit PCM；别的格式原样放过、增益记 0（不猜、不硬改）。

### 3. 音频设备变化

- `wt-audio.js`：监听 `navigator.mediaDevices.devicechange` → 立刻暂停（记下 BGM / 语音位置）→
  等 600ms 让系统切完 → 换新 `Audio` 元素重建并续播；续不上走 `__saveHint` 提示「重播这句」。
- `wt-voice.js`：新增 `suspendForDevice()` / `resumeAfterDevice()`（从原位置续播）。
- 顺手修：`WA2.audio` 的 `current / enabled / device` 以前被 `_exp` 覆盖掉，静音开关读写的其实是
  对象上临时挂的属性；现在补成 getter/setter，和模块内部状态一致。

## 没做 / 边界

- 设备变化只在浏览器给 `devicechange` 时才有动作；系统静默换默认设备不会触发。
- 响度归一化在服务端做，新合成 / 首次命中缓存多几十毫秒；没有做离线批量重算（缓存本来每次启动清空）。
- 过渡关闭 = 直接切，不是「慢速淡入」；曲线用线性，没做缓动。
