# 设计：分层人格提示词（base + 情境切片）

> 2026-11-02 记录。这是一个**通用思路**，不绑定具体角色；任何人都可以用它给自己的
> 角色卡做「按情境细分」的人设。本仓库的实现只是其中一个参考。

---

## 一、要解决的问题

一整份人设通常只有两种写法：

- **写短**：省 token，但角色扁平，换个场景/关系就出戏；
- **写长**：细节多，但每轮都全量注入，贵，而且模型容易在长文里抓错重点。

同一个角色，面对不同的人、处在不同的关系阶段、不同的场景，说话方式本来就不一样。
把这些差异**显式拆开、按需注入**，可以同时得到「更像」和「更省」。

---

## 二、结构

```
persona/
├── base.txt            不变的核心：身份、底线、说话方式、绝对不做的事
├── relation_1..N.txt   关系阶段切片（陌生 → 熟悉 → 亲密 → 长期）
├── scene_*.txt         场景切片（工作 / 家里 / 公开场合 / 约会）
├── mood_*.txt          情绪切片（平静 / 吃醋 / 低落 / 生气）
└── who_*.txt           对象切片（熟人 / 陌生人 / 长辈 / 同事）
```

**每轮只注入 `base` + 每个维度最多 1 个切片。** 切片只写「和 base 不一样的地方」，
不重复 base 里已经有的内容。

---

## 三、怎么选（关键）

| 方式 | 成本 | 适用 |
|---|---|---|
| 便宜规则（关键词 / 当前场景 / 称呼） | 0 | 明确信号：场景标签、对方称呼、明显事件 |
| 云端分类器（低频、异步） | 每 N 轮一次 | 关系阶段、情绪这种需要理解的 |
| 状态缓存（上次结果） | 0 | 两次判断之间沿用 |

推荐组合：

- 每轮先用便宜规则命中「明确信号」，命中就更新；
- 没命中时，**每 N 轮**（例如 40 轮）把最近一段对话发给云端，只回一个枚举标签；
- 分类在后台跑，结果下一轮生效，不拖慢聊天；
- 维度轴**只升不降**，到顶就封顶、不再调用；
- 读档 / 新游戏时重置，避免串档。

云端分类器的提示词只要「枚举 + 一句判定」，输出 1~2 个 token；窗口截断到几千字，
频率可调。这样均摊成本远低于每轮把全部切片塞进上下文。

---

## 四、为什么更省

以 4 个切片、整份约 900 token 为例：

| 方案 | 每轮人设 token |
|---|---|
| 整份全量 | ~900 |
| base + 1 个切片 | ~500 |
| base + 1 个切片 + 分类器均摊（每 40 轮） | ~500 + 100 ≈ 600 |

切片越多、整份越长，省得越多；分类器的成本只和「多久判一次 + 窗口多大」有关。

---

## 五、为什么更像

- 角色在不同关系/场景下的差异被**写成明确规则**，模型不用从长文里自己推断；
- 当前情境下只看到「该看到的那一面」，不会被无关切片干扰；
- 切片是独立的，改一个场景不会牵动全局。

---

## 六、通用化：让别人也能用

- 角色卡作者自己定义**维度**（关系 / 场景 / 对象 / 情绪…）和**切片文件**；
- 选择器可插拔：没有云端时，退回关键词/状态规则也能跑；
- 维度数量别贪多：每加一个维度就多一次判断和一份状态，**1~2 个维度**通常最划算；
- 「无限细分」可以，但要给总长度和切片数量设上限，否则判断成本会超过省下的 token。

---

## 七、踩坑与约束

1. `base` 只写不变的东西；可变内容全部放切片，否则切片会互相打架。
2. 切片之间不能矛盾；冲突时以 `base` 为准。
3. 分类器输出必须是枚举，`max_tokens` 压到个位数，`temperature=0`。
4. 分类要异步；同步调用会直接拖慢聊天。
5. 状态要么放运行时缓存（读档重置），要么放存档 `meta`；别两份都写。
6. 分类窗口只看最近 N 轮，更早的信息靠状态缓存或记忆书，不要越带越长。
7. 到顶（最亲密/最终形态）后停止调用，避免无意义的重复判断。
8. 切片文件属于角色设定，**是否公开由作者决定**；机制和切片内容分开管理。

---

## 八、本仓库的参考实现

- `program/src/persona_ctx.py`：读 `persona/base.txt` + 命中的 `stageN.txt`，拼进 system；
- `program/src/persona_stage.py`：每 40 轮（`WA2_STAGE_EVERY` 可调）异步问云端要一个
  1~4 的标签；只升不降、到 4 封顶；本地关键词只做「明确的封顶」和失败兜底；
- `program/tools/test_persona_stage.py`：触发、封顶、失败兜底的回归测试。

具体切片内容不在仓库里（属于角色设定，作者本地维护）。这套结构可以直接套到别的角色：
换掉 `base` 和切片文件、改一下分类器的枚举定义即可。
