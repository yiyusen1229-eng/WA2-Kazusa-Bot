# 更新日志 2026-11-05 17:41

> 主题：**修「全屏失效」**——窗口接口拿到空壳 `main` 模块，全屏 / 最大化点了没反应。
> 范围：`main.py` 顶部 6 行、`api_window.py` 取窗口方式、新增 1 份自测 + 1 条用例。
> 版本号未动（仍是 `2026-11-05.1`），未 push、未出补丁。

## 一、用户报的现象

「全屏失效了」。复现（真机，用户 17:25 的操作留下的日志）：

- 点标题栏「最大化」连点 10 次 → 每次都回 200，窗口纹丝不动；
- 「环境设置 → 画面设置 → 全屏模式 / 窗口模式」来回切 → 同样没反应；
- 关窗、最小化正常。

## 二、根因：`import main` 拿到的是另一份模块

`python main.py` 起的时候，主文件在 `sys.modules` 里叫 **`__main__`**。
拆 mixin 时 `api_window.py` 写成了：

```python
import main            # ← 把 main.py 又执行一遍，得到第二份模块
w = main._WINDOW       # ← 这份里没有 _WINDOW
```

于是每个窗口请求都回：

```json
{"ok": false, "error": "module 'main' has no attribute '_WINDOW'"}
```

为什么一直没被发现：

| 入口 | 走的通道 | 结果 |
|---|---|---|
| 关闭 / 最小化（标题栏） | pywebview 桥接 `_Api.win`，HTTP 只是兜底 | 桥接通，照常工作 |
| **全屏 / 最大化** | **只有 HTTP** `/api/window` | 后端 `w is None` 直接返回，**静默失效** |

HTTP 状态码是 200（错误在 body 里），日志里也只有一行正常的 `GET ... -> 200`，
所以自测、日志、界面三处都不报错——典型的静默失效。

## 三、改动

| 文件 | 改动 |
|---|---|
| `program/src/main.py` | 顶部加 6 行：`if __name__ == "__main__": sys.modules.setdefault("main", sys.modules["__main__"])`，之后任何 `import main` / `from main import ...` 都拿到真身 |
| `program/src/api_window.py` | 取窗口改为 `getattr(winutil._main_module(), "_WINDOW", None)`（`dragbegin` 的 `_API`、`resize` 的 `_WINDOW` 一并改），不再 `import main` |

## 四、验证

隔离探针（同参数的无边框窗口 + pywebview 6.2.1）先证明 **pywebview 本身没坏**：
`toggle_fullscreen()` 能把窗口从 `3168×1707@(61,66)` 切到 `3840×2160@(0,0)` 再切回来。

然后端到端（起真程序、走 HTTP、量窗口矩形）：

| 请求 | 修复前 | 修复后 |
|---|---|---|
| `/api/window?act=state` | `{"ok": false, "error": "module 'main' has no attribute '_WINDOW'"}` | `{"ok": true, "maxed": false, "fullscreen": false}` |
| `action=fullscreen&on=1` | `ok:false`，窗口不动 | `{"ok": true, "fullscreen": true}`，窗口 → 满屏 |
| `action=fullscreen&on=0` | 同上 | `{"ok": true, "fullscreen": false}`，窗口 → 1024×576 居中 |
| `act=togglefull` | 同上 | `{"ok": true, "fullscreen": true}` |

自测：`run_smoke.py` **33 项全绿**（29 份用例）。

## 五、留下的经验

1. **「HTTP 200」不等于成功**：接口把错误写在 body 里，前端 `.then` 又不看 `ok`，
   这条链路坏了也没人喊。窗口 `/api/window` 的返回体里的 `ok` 应当被前端当回事
   （现在 `__setWinMode` 只看 `fullscreen` 是否存在）。
2. **`from main import X` 在这套代码里是「快照 + 可能拿到空壳」**：真身是 `__main__`。
   顶层的别名把这类问题一次收掉，但新写的 `api_*.py` 还是要用
   `winutil._main_module()` 摸窗口 / API 对象。
3. **只有一条通道的功能最脆**：关闭 / 最小化有桥接 + HTTP 双通道所以没坏，全屏只有 HTTP 就整条死掉。
