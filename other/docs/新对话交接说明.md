## 一、项目是什么

《白色相簿2》冬马和纱的桌面聊天程序：游戏原版 UI + 立绘 + GPT-SoVITS 日语语音 + 中文对照。
技术栈：Python（pywebview + WebView2）+ 纯 HTML/CSS/JS 前端，舞台固定 **800×450**，按 16:9 缩放。

## 五、这次踩过的坑（务必先读）

### 5.1 多余的 `</div>`

清空存档界面时多插入一个 `</div>`，导致外层容器提前关闭：

- 系统设置界面出现黑边
- 全屏错位
- 主菜单一度也有黑边

**改 HTML 后必须做配平检查**：

```python
len(re.findall(r"<div\b", s)) == len(re.findall(r"</div>", s))
```

### 5.2 换算系数别搞混

- 用户给的截图常见尺寸：**1708×961**（预览） 或 **2730×1536**（原生）
- 舞台 800 宽
- 从 1708 图读数 → 系数 `800/1708 = 0.4684`
- 从 2730 图读数 → 系数 `800/2730 = 0.2930`（即 ÷3.4125）

搞混会得到 1.6 倍的误差（槽位最初就是这样放错的）。

### 5.3 页签三态来自原图，不要染色

`sys_01021.tga` 640×96 = 10 列 × 3 行：

| 行 | 最亮像素 RGB | 用途 |
|---|---|---|
| 0 | (182,250,251) 青 | 当前页 |
| 1 | (183,189,104) **黄** | 悬停 |
| 2 | (101,135,141) 暗青 | 常态 |

**黄色是素材自带的**，不需要 CSS 滤镜。用 `background-position` 取图在界面隐藏时会失效（`offsetWidth=0`），
所以现在用「预生成整条图片 + 两张 `<img>` 叠加」的方式。

### 5.4 需要「延长」的 UI 元素，在图片里延长

白线原本用 CSS 平铺拼接，接缝永远对不齐。最终做法：

```
取原图线条所在行 → 4 倍超采样 → 用最右端一列像素逐列向右复制 → 存成一张图
```

一张图直接铺上去，物理上不可能有接缝。

### 5.5 用户反馈「没变」时先查三件事

1. exe 时间戳是否晚于他的截图时间
2. CSS 里是否有残留的 `display: none` 覆盖新规则
3. 目标规则是否真的进了打包目录（`release\...\_internal\ui2\`）

### 5.6 打包前杀进程

`和纱.exe` 运行时文件被占用，`build_portable.py` 会在 `shutil.copytree` 处报 `FileExistsError`。
先 `Stop-Process`，必要时手动删 `release\和纱绿色版`。

## 六、关键接口

| 接口 | 说明 |
|---|---|
| `GET /api/text?t=…&plain=1` | 文字渲染成字模 PNG（所有 UI 文字都走它） |
| `POST /api/modelcfg` | 模型配置（chat/voice/mt 三段） |
| `POST /api/chat` | 对话，返回 `reply/reply_zh/emotion/scene/outfit` |
| `GET /api/tts?t=&emo=` | 合成语音 |
| `POST /api/session/save` | 存档 `{slot, messages, meta}` |
| `GET /api/session/load?slot=` | 读档 |
| `GET /api/session/list` | 存档列表 |

`js_api` 上挂了 `window.pywebview.api.drag_rect/drag_move`（拖动，进程内调用，比 HTTP 快）。

**注意**：`js_api` 对象的公有属性会被序列化——不要挂原生窗口对象（曾导致无限递归、内存 2.9 GB、卡死）。

## 七、工作方式的约定

1. **改完必须自己先看一眼**：可以起 `--serve-only` 服务，用浏览器打开 `http://127.0.0.1:8771/game/` 加临时 `#save` 钩子截图验证，不要只靠用户反馈
2. **一次只改一个量**：位置/尺寸/层级分开
3. **不要用估算代替测量**：读数是像素，换算写进注释
4. **用户对回归极敏感**：已确认的元素不要再动
5. **release 不要每次自动更新**：用户要求「我说更新再更新」
