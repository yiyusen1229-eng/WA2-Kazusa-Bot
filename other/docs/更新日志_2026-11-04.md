# 更新日志 2026-11-04 · 省 token 与模块化

> 这一轮不加功能，只降成本：**不输出截图**、**按架构分层索引只读一层**、**清掉废弃文档**。
> 补丁：`other/docs/patches/2026-11-04_更新补丁.patch`（基线 `5d3e71f`）。
> 只动文档与工具，不动运行时代码；素材、角色资源、存档仍不入库。

## 一、起因

项目文档 46 份 / 350 KB，交接文档单份 32 KB，README 21 KB；再加每次对话的历史和截图，
新会话一进场上万 token。目标是：**新会话只读 1 页就能开工，动代码只读一层**。

## 二、做了什么

### 1. 代理不再输出截图（硬规则）

写进 `AGENTS.md` 和 `交接速览.md`：界面问题看探针返回的 JSON 数字
（节点数、高度、能否滚动、`naturalWidth>0`、报错列表），只有用户明确说“给我看图”才 `--shot`。
一张截图上千 token，是单项最贵的支出。

### 2. 架构分层索引（`other/docs/架构/`，8 份，每份 1.5～3 KB）

| 文件 | 层级 | 内容 |
|---|---|---|
| `00_总览.md` | 总架构 | 一层数据流图、7 个一级模块表、**按任务找入口** |
| `01_后端与接口.md` | 一级 | `main.py` 的 § 小节、29 个接口分组、改法 |
| `02_对话管线.md` | 二级 | 一次请求的 5 步 system 拼装顺序、演出侧 |
| `03_记忆与世界书.md` | 三级 | 记忆书/世界书/人设/检索 四套东西的分工与默认值 |
| `04_角色与资源.md` | 三级 | 角色文件夹结构、立绘/语音/权重 |
| `05_前端界面.md` | 二级 | 7 个界面、js/css 分工、字模图与 `?v=` 机制 |
| `06_工具自测与发布.md` | 三级 | 工具清单、6 个自测、发布流程 |
| `07_文件与格式.md` | 四级 | 存档 / 角色文件 / 世界书 / 立绘索引 / 配置 的格式 |

用法：`00_总览.md` 里有一张「想改什么 → 读哪份」的表；改后端不用读 `game.js`（68 KB），
改前端不用读 `main.py`（80 KB）。

### 4. 上一提交的省 token 三件套（一并记在本轮）

- `other/docs/交接速览.md`（1 页 / 3.3 KB）：现状、目录、命令、坑、待办、省钱
- `AGENTS.md`（根目录）：代理须知、命令、省钱规则、不许动的东西
- `program/tools/digest.py`：`--outline` / `--slice` / `--patch`，把 18.9 KB 补丁压成 7 行摘要

## 三、效果（同一任务对比）

| 场景 | 之前 | 现在 |
|---|---|---|
| 新会话了解项目 | 读 32 KB 交接文档（≈1 万 token） | 读 3.3 KB 速览（≈1 千 token） |
| 改一个后端接口 | 读 `main.py` 80 KB | 读 `01_后端与接口.md` 3 KB |
| 看一个补丁 | 贴 19 KB 全文 | `digest.py --patch` 7 行 |
| 验证界面 | 截图（上千 token/张） | 探针 JSON（几百 token） |


### 5. 代码拆分（第一步）

- 新增 program/src/text_parse.py：split_scene / split_emotion / split_action / split_thinking /
  ja_clean / ja_ok（7 个纯函数，不碰全局和文件）
- main.py 从 **1955 行减到 1875 行**，这些函数改成从新模块导入（_ja_clean/_ja_ok 保留别名，
  调用方不用改）
- 6 个自测全过
- 详细拆分路线（后端分 7 步、前端分 3 步、每步怎么验证）写进 other/docs/架构/08_代码拆分计划.md

> 为什么不一口气拆完：_chat（169 行）和 game.js（68 KB）都依赖大量闭包/全局，
> 一次大改很容易出隐藏 bug；计划里每步都要求 6 自测 + 探针，拆坏就 revert。
