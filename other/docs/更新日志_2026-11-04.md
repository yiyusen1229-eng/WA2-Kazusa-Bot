# 更新日志 2026-11-04 · 省 token 与模块化

> 这一轮不加功能，只降成本：**不输出截图**、**按架构分层索引只读一层**、**清掉废弃文档**。
> 补丁：`other/docs/patches/2026-11-04_更新补丁.patch`（基线 `5d3e71f`）。

## 一、起因

项目文档 46 份 / 350 KB，交接文档单份 32 KB，README 21 KB；再加每次对话的历史和截图，
新会话一进场上万 token。目标是：**新会话只读 1 页就能开工，动代码只读一层**。

## 二、做了什么

### 1. 代理不再输出截图（硬规则）

写进 `AGENTS.md` 和 `交接速览.md`：界面问题看探针返回的 JSON 数字
（节点数、高度、能否滚动、`naturalWidth>0`、报错列表），只有用户明确说“给我看图”才 `--shot`。
一张截图上千 token，是单项最贵的支出。

### 5. 代码拆分（第一步）

- 新增 program/src/text_parse.py：split_scene / split_emotion / split_action / split_thinking /
  ja_clean / ja_ok（7 个纯函数，不碰全局和文件）
- main.py 从 **1955 行减到 1875 行**，这些函数改成从新模块导入（_ja_clean/_ja_ok 保留别名，
  调用方不用改）
- 6 个自测全过
- 详细拆分路线（后端分 7 步、前端分 3 步、每步怎么验证）写进 other/docs/架构/08_代码拆分计划.md

> 为什么不一口气拆完：_chat（169 行）和 game.js（68 KB）都依赖大量闭包/全局，
> 一次大改很容易出隐藏 bug；计划里每步都要求 6 自测 + 探针，拆坏就 revert。


### 6. 架构映射表 + 落位硬规矩

- 新增 program/tools/arch_map.py：扫 program/src，自动生成
  other/docs/架构/映射表.md（31 个文件，7.5 KB）
- 表里列：**层级 / 文件 / 行数 / 职责 / 导出 / 依赖 / 被谁调用**；末尾有「待拆（行数最多的 8 个）」
- --check 用来防止表过期（提交前跑，不过就 --write）
- 写进 AGENTS.md 的硬规矩：
  1. 目录即层级（core / chat / api / character / ui），不许往 main.py 继续加
  2. 单文件上限 **400 行**，超过必须拆
  3. 新文件必须登记进 rch_map.py 的 LEVELS / UI_LEVELS
  4. 改完代码跑 rch_map.py --write，提交前 --check
  5. 只读一层：先看映射表的「层级 / 被谁调用」再决定读哪个文件

> 当前待拆前三：main.py 1879 行、game.js 1830 行、opt.js 1022 行。

  只在方法开头注入 `from main import (...)` 拿运行时全局（`_WINDOW` / `STORY` / `_TEXT_CACHE` 等）
- 验证：6 个自测全过；`/api/ping`、`/api/text`(2231B)、`/api/window`、`/api/character/list`、
