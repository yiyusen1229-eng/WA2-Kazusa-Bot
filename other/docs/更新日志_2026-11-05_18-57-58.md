## 三、口径（这三条是这一项的全部价值）

1. **只删程序能自己再生成的东西**
   运行时缓存三份、字模缓存、语音缓存、`app-*.log`（**今天正在写的那份不删**）、`perf-*.csv`、
   `crash_*.log`、`asset_report.json`、`work_scratch/` 里的东西。
   存档 / 人设 / 世界书 / 记忆书 / 素材 **一个字节都不动**。

2. **导出默认脱敏、默认不带对话**
   文本统一过 `logpack.scrub()`（密钥 / 用户名 / 绝对路径），`config.json` 的 `api_key` 先打码；
   `turns>0` 才把 `sessions/*.json` 打进 zip，且导出前前端还要一次 confirm。
   素材（立绘 / 语音 / CG）不进 zip —— 太大，走「特别模式 → 角色包导出」。

3. **删角色不是真删**
   整个文件夹 `os.rename` 到 `characters/_deleted/<角色>_<时间>/`（同盘瞬时），想撤回原路搬回；
   同时清 `cache/<角色>/`。三道确认：前端 confirm → 手打角色名 → 后端比对 `confirm`。
   当前在用的角色不让删；id 带 `/ \ .. : * ? " < > |` 一律拒绝。

## 五、坑

1. **`overview()` 里别用 `chars` 当局部变量**：函数签名就有 `chars=` 参数，
   我第一版写了 `chars = []` 当累加器，参数被就地覆盖，概览永远只返回"传进来的那份"。
   自测里 `概览两个角色` 当场炸出来 —— 这就是为什么自测要传参、别依赖真实目录。
2. **概览的数字必须等于真删的量**：`runtime` 项一开始按整个 `cache/` 目录算（含
   `cache/<角色>/` 的语音缓存），但 `clean()` 只删三份 json —— 显示 5 个文件、实际删 3 个，
   用户会以为丢了两份。现在 `runtime` 只统计 `RUNTIME_FILES`。
   同理 `scratch`：既然清理是「扫空 work_scratch」而不是只删 `tmp/`，统计也按整个目录算。
3. **`_deleted/` 目录要排除在角色列表外**：`_char_ids()` 跳过以 `_` 开头的目录，
   否则删过的角色会顶着 `和纱_2026-11-05_…` 的名字回到列表里。
