## 做了什么

### 1. 像素测量从「手工流程」变成一条命令

`program/tools/measure_ui.py`（纯 Pillow，**项目 venv 没有 numpy 也能跑**）：

```powershell
python program\tools\measure_ui.py profile 原图.jpg                # 行距 / 峰位 / 槽位宽 / 宽高比
python program\tools\measure_ui.py verify 渲染截图.png              # 先裁黑边再量
python program\tools\measure_ui.py compare 原图.jpg 截图.png --asset 1896x288   # 偏移 + 宽高比
```

- 行剖面取中位数压掉文字 → 找周期峰定行距；列剖面 50% 交叉点定槽位宽；
  宽高比必须等于素材宽高比（差 >1% 判「被拉伸」）。
- **稳健性**：先轻度平滑、按显著性过滤假峰、用「相邻差值众数」+ 等差距链；
  凑不出稳定周期就明说「不是整帧原图 / 不是这个界面」，不硬给数字。
- `compare` 输出：偏移量（逐峰中位）、周期比、宽比、宽高比差；任一项 >1% 退出码 1。

### 2. 性能采样

`program/src/perf.py`：每 20 轮（`WA2_PERF_EVERY`）在**后台线程**往 `logs/perf-<日期>.csv` 记一行：

```
ts,uptime_s,round,rss_mb,threads,handles,gdi,user,text_cache,tts_files,tts_mb,mem_entries,chat_ms,chat_tokens
```

- 内存 / 峰值、线程数、进程句柄、GDI 与 USER 对象（字模渲染主要吃 GDI，涨个不停就是漏了）、
  字模缓存条数、TTS 缓存文件与体积、记忆条目数、上一轮耗时与 token。
- `WA2_PERF=0` 整个关掉；写文件失败只记 WARN；不会抛进对话流程。
- 接入：`api_chat` 一轮结束调 `perf.maybe()`；`diag.snapshot()` 多一个 `perf` 块（调试面板能看）；
  `logpack` 按同一天数清理 `perf-*.csv`，并把它打进诊断包。

## 修的一处「假数据」

第一次真机冒烟时 `handles` 一列一直是 `0`：`GetProcessHandleCount` 没设 `argtypes`，
`HANDLE`（64 位）被 ctypes 按 C int 传进去截成 -1，调用失败但没报错——这种「恒 0 的指标」
比没有更坏（会让人以为没有句柄泄漏）。补上 `argtypes/restype` 后真机是 133，
并在自测里加了一条「Windows 上句柄数 > 0」。

## 没做 / 边界

- 「音频句柄」没进 CSV：那是前端 `Audio` 对象，后端看不到；语音状态看调试面板「语音」行。
- 采样是每 N 轮一次，不是连续采样；短会话不会产生数据。
- 内存 / 句柄 / GDI 都是 Windows API；别的平台这几列是 0。
- 像素工具只认真实整帧 + 同尺寸舞台；拼图 / 带黑边 / 非 16:9 会先警告或拒绝给结论。
