> 主题：**字幕两句、语音只有半句**。
> 结论：合成端不截断（实测证明）；真正能截断的是 `ja_clean()` 的两条规则，已修。
> 范围：`text_parse.py`（`ja_clean`）、`tools/test_text_parse.py`。

## 一、先证明合成端是完整的

直接用应用同一套参数打 GPT-SoVITS（`text_split_method=cut5`，参考音频 `calm`）：

| 文本 | 时长 |
|---|---|
| `…冗談だ。` | 1.56 秒 |
| `…冗談だ。ちゃんと起きる。` | **3.24 秒** |
| `…冗談だ。ちゃんと起きる。もう少しだけ、こうしていさせて。` | **6.70 秒** |
| `「…冗談だ。」「ちゃんと起きる。」` | 3.00 秒 |

再走应用自己的 `/api/tts`（端到端，真起了一个后端）：

| 请求 | 时长 |
|---|---|
| 两句构造 `…冗談だ。ちゃんと起きる。` | **2.20 秒** |
| 首句构造 `…冗談だ。` | 1.16 秒 |

两句 ≈ 首句的 1.9 倍 —— **两句都念了**，没有截断。
（顺带发现：`cut0`（不切分）会截断，两句只输出 1.60 秒；应用用的是 `cut5`，没问题，**别改成 cut0**。）

## 二、能截断的是 `ja_clean()`，两处

`text_parse.ja_clean()` 是「中→日 翻译结果清洗」，给 TTS 用的是它的输出。它原来有两条规则会砍台词：

1. **按第一个句号截断**：

   ```python
   if "。" in x[:-1]:
       x = x.split("。")[0] + "。"     # ← 两句变一句
   ```

   注释写的是「句号后还有解释的, 只取第一句」，但它是无条件生效的 ——
   任何两句台词都会被砍成一句半。

2. **从句中逗号截断**：停止词列表里有 `"，"` / `","`，正常句子里的停顿也会被当解释尾巴砍掉。

现在：
- 删掉「按句号取第一句」；
- 停止词只留真正的解释标记（`翻訳` / `場合は` / `注意` / `つまり` / 全角/半角冒号）。

## 三、还有一个「看起来像截断」的原因（已在上一版解决）

旧版本里**字幕是另一次翻译的产物**：日文原句是模型说的，中文是翻译模型事后译的。
两边字数本来就对不上（翻译常会把一句扩成两句），于是「字幕两句、语音只有一句」。
今天的双语改造（`<ja>` + `<zh>` 由模型自己一起给）把这个错配从根上去掉了 ——
**需要重启才生效**。
