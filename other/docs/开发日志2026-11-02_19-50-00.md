# 开发日志 2026-11-02 19:50

> 主题：角色「完全自包含」+ 三个反馈问题的修复（查看文件指旧目录 / 提示压按钮 / 切回角色名字没变）。

## 1. 为什么之前不算自包含

上一版只把 `char/<kind>/` 搬进了 `characters/<角色>/`，但程序读人设 / 世界书时仍然是
**「角色文件夹里有就用，没有就回落到程序自带的 `persona/`、`worldbook/`」**：

- 和纱的角色文件夹是空的（她的人设一直放在 `program/src/persona/`）→ 实际读的是自带的
- 所以配置里点「查看文件」打开的是 `persona/base.txt`、`worldbook/worldbook.json`
  （看起来「还是原来的」）

## 2. 现在的做法：角色文件夹是唯一来源

`characters.py` 新增 `set_seed_sources()` / `seed_character()`：

- main 启动时把 `persona/`、`worldbook/worldbook.json` 作为**模板**交给 characters
- 某个角色的 `prompt/` 还是空的 → 把模板复制进去（`base.txt`、`stage1~4.txt`、
  `persona_core.txt`、`persona.txt`）；`worldbook/worldbook.json` 同理
- 触发点：首次启动迁移、切换角色、新建角色 —— 保证「每个角色点开都自带一份完整设定」
- 复制之后**程序只读角色文件夹**：`persona_ctx.prompt_dir()` 优先角色目录，
  `persona_ctx.load_worldbook()` 先看角色的 `worldbook/`；自带的那两份只当模板

`char_res.prompt_text()` 多了一条判断：角色 prompt/ 里有 `base.txt` 时返回空串，
交给 `persona_ctx` 拼「base + 当前关系阶段」，否则只会读到 base、阶段文件等于白放。

**「查看文件」改成一致规则**（`special_files.open_target`）：
五类一律打开当前角色文件夹里的那一类，有文件就选中它，没有就打开空目录让人往里放。
状态行也跟着改：文件在角色文件夹里 →「（角色文件夹）」；还没有 →「当前：还没设置」。

## 3. 三个反馈问题

### 3.1 提示消息压在「切换角色 / 新建角色」按钮上

`#specialScreen .spSaved` 原来是 `right:0; top:1px` —— 正好在右栏标题行右侧，
也就是新按钮的位置上。改成 `top:18px`，落在标题行和「角色名称」之间的空档里。
实测 rect：按钮 `top 126–141`，提示 `top 144–158`，不再重叠。

### 3.2 切回和纱，角色名称还是「新角色」

排查到三个原因，全部处理：

1. **选窗口默认停在总目录**：直接点确定返回的是 `characters/` 本身，被后端拒绝；
   当时提示又被按钮压住，所以看起来「什么都没发生」。
   现在这种情况返回 `cancelled + 明确提示`（「请双击进入一个角色文件夹再点确定」）。
2. **界面没重读**：只有成功才刷新。现在取消 / 失败也会重新拉
   `/api/special/name` + `/api/special/status`，「角色名称」永远显示后端真实的当前角色；
   取消时还会提示「已取消，当前角色：和纱」。
3. **选择窗口可能藏在游戏窗口后面**：PowerShell 里加了一个 1×1 置顶 Owner 窗体，
   对话框不会再被压到后面。

另外把选择结果改成走 **UTF-8 临时文件**回传（不再靠 stdout），
中文文件夹名（和纱）不会因为控制台代码页被转坏 —— 实测 `equal: True / isdir: True`。
