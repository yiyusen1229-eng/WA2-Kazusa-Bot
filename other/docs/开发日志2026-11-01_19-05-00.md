## 一、上下文预算：先调到 16000，随后按用户要求改回 32000

> **最终状态：仍是 32000 / 19200 / 8000。** 这一节记录的是当时的调整过程，
> 后来用户明确要求改回原值（当时误把"用户问我自己的 token"理解成"程序太费"）。

用户提到 token 消耗得有点快。查下来原因是**发给模型的量**：切到记忆书模式后
每轮要带一整个"最近段"，窗口按 32K 上下文算，等于每轮最多带 8000 token。

deepseek-flash 实际支持 1M 上下文，32K 只是当初保守取的数 —— 但**窗口越大，
每轮花的越多**，收益却很小（几十轮之前的对话，模型本来也抓不住重点）。

| | 之前 | 现在 |
|---|---|---|
| 云端上下文 | 32000 | **16000** |
| 触发阈值（60%） | 19200 | **9600** |
| 最近段（25%） | 8000 | **4000** |
| 条目上限（12%） | 3840 | **1920** |

本地模型那一档（4096）没动。

> 这是 `memory.py` 里的 `DEFAULTS`，也可以用 `program/memory.json` 覆盖。
> 用户可调的界面和"每轮大概花多少 token"的参考值仍然记在 `未完成功能.md` 第九节。

### 关于"花得快"的真相

token **数量**确实涨了（窗口从 16 条消息变成数千 token），但**钱**主要花在
"新出现的 token"上：DeepSeek 会自动缓存重复的前缀，命中价是未命中的 1/50
（¥0.02 vs ¥1 / 百万）。实测一次 1572 token 的往返只要 **¥0.0005**。

## 二、瘦身：删掉 207MB 重复素材

开发运行时 `build_env/ui2/assets` 是 `res/assets` 的整份复制（207MB），
每跑一次 `run_dev.py` 就要重新复制一遍。

改法：

- `main.py` 新增 `ASSETS_DIR`：优先读环境变量 `WA2_ASSETS_DIR`，否则退回 `ui2/assets`
  （打包版没有这个变量，行为和以前一致）
- `translate_path` 里 `/game/assets/**` 走 `ASSETS_DIR`
- `run_dev.py` 不再复制素材，只是启动时把 `WA2_ASSETS_DIR` 指向 `program/res/assets`

效果：`build_env` 从 **306.8MB → 99.6MB**，每次启动少复制 896 个文件。
