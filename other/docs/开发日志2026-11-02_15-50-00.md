## 三、UI 色差分析（只分析，没改）

用纯色页面测 WebView2 的实际输出（真机截图，PNG，无 ICC）：

| 输入 sRGB | 截图里读到的 |
|---|---|
| `#00909E` (0,144,158) | (53,141,157) |
| `#FF0000` (255,0,0) | (240,53,27) |
| `#808080` | (128,128,128) 不变 |
| `#FFFFFF` | (255,255,255) 不变 |

这正好是 **sRGB → Display P3** 的数值：sRGB 纯红在 P3 里约 (234,51,35)，我们测到 (240,53,27)；
中性色不变也符合色域映射的特征。

对照：底部 Leaf 栏的素材文件是 (0,144,158)，游戏截图里是 (0,145,160) —— **素材本身没错**；
我们页面渲染出来变成 (53,142,158)，就是这一步转换造成的。

结论：

1. **主因是颜色管理**：WebView2 会把 sRGB 内容按显示器 ICC 转到广色域（这台是 FY32UMC，
   应该是 P3 级面板）；游戏是 D3D9，不读 ICC，直接把 sRGB 数值写到屏幕上 —— 所以在广色域屏上
   游戏显得更艳，我们的界面显得偏灰。
2. 次因：半透明 UI（页签 alpha≈0.7）叠在不同的背景上 —— 游戏叠实时场景，我们叠静态背景，
   混出来的颜色自然不同；游戏对背景的压暗程度也要一致才行。
3. 截图/JPEG 只影响边缘，不影响这种大面积纯色。

可选修法（都还没做）：

- 启动 WebView2 时加 `--force-color-profile=srgb`（`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`），
  让浏览器按 sRGB 输出，和游戏一致；代价是其它网页内容也不再做色彩管理。
- 或者把 Windows / 显示器的配置切到 sRGB（影响全局）。
- 或者接受现状（我们的颜色在色彩管理意义上是"正确"的，游戏是过饱和的）。
- 文档截图如果要给别人看，保存前把显示空间转回 sRGB / 嵌入 ICC。
