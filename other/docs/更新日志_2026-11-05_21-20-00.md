# 更新日志 2026-11-05 21-20-00 · 一键更新（不用再自己下补丁）

> 版本 `2026-11-05.2` 之后的本地改动（发布时按第 12 条另立版本号）
> 一句话：标题栏那条更新提示，点一下就会自己更新到最新版，**漏几版都没关系**。

## 为什么不用补丁

补丁是「对某个基线」的 diff。用户如果连着一两次没更新，基线对不上就 `git apply` 失败——
这正是「连跳两个版本怎么打补丁」的问题。所以客户端改成直接取**最新整份代码**：

| 安装形态 | 做法 |
|---|---|
| `git clone` 的（有 `.git` + 装了 git） | `git fetch --depth=1 origin master` → `git reset --hard FETCH_HEAD` |
| zip 安装的（没有 `.git`） | 下载 `codeload.github.com/<repo>/zip/refs/heads/master`，只覆盖代码/文档白名单 |

## 它保什么、不碰什么

- **不碰**：`program/build_env/`（角色、存档、缓存、venv）、`program/res/`（素材）、`program/logs/`
- **只覆盖**：`program/src`、`program/tools`、`program/tests`、`other/docs` + 根目录几个文件
- 覆盖前自动备份到 `program/work_scratch/update_backup_<时间>/`，中途失败自动还原
- 上游删掉的文件本地也会删（只删代码/文档后缀，不留孤儿）

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/update` | 查版本；多了 `auto`（能不能自动更新）和 `mode`（`git` / `zip`） |
| `POST /api/update/apply` | 后台开始更新，立刻返回 |
| `GET /api/update/status` | 进度：`running / percent / stage / message / ok / error / version` |

## 边界

- git 模式会**丢弃本地未提交的代码改动**（角色/存档/素材不在版本控制里，不受影响）；
  自己改过代码的用户建议用 zip 安装形态，或者先提交再更新。
- zip 模式依赖 GitHub 可访问；失败会保留旧代码并提示「点此打开下载页」手动处理。
- 更新完要**重开程序**才生效（运行中的进程还拿着旧模块）。
