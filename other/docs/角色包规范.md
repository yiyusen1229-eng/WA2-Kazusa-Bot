# 角色包规范（`wa2-char-pack` v1）

> 一个角色包 = **一个 zip**，里面是**这个角色本身**：提示词、世界书、记忆书、立绘、参考音频。
> **不含**存档、设置、API key、日志、缓存 —— 导出端是白名单，不是黑名单。
>
> 实现：`program/src/char_pack.py`。示例包：[`examples/min_pack/`](examples/min_pack/)。

## 1. 目录布局

```
雪见.zip
├── manifest.json          可选（导出时总会写；导入端没有也能吃）
├── name.txt               显示名（≤12 字）；没有就用 manifest.name / 压缩包文件名
├── prompt/
│   ├── base.txt           必需：角色本体（没有就用自带模板铺一份，不至于导入成空角色）
│   ├── stage1.txt … stage4.txt   可选：关系阶段覆盖（阶段越高越亲近）
│   └── style.txt          可选：说话风格补充
├── worldbook/
│   └── worldbook.json     可选：世界书条目数组
├── memory/
│   ├── standing.json      可选：关系进度（导出时会脱敏，见 §5）
│   └── 记忆书.txt          可选：常驻记忆书正文
├── portrait/              可选：立绘，按服装分子目录
│   ├── 校服/calm.png 毒舌.png …
│   └── index.json         可选：服装/表情索引；没有就扫目录
└── voice/                 可选：GPT-SoVITS 参考音频
    ├── ref.txt            可选：参考音频清单
    └── *.wav / *.mp3
```

> 允许**多包一层**：如果你把整个角色文件夹压进去（条目是 `雪见/prompt/…`），
> 导入时会自动剥掉这一层（当且仅当所有条目都在同一个顶层目录下、且那个名字不是
> `prompt/worldbook/memory/portrait/voice`）。

## 2. `manifest.json`

```json
{
  "format": "wa2-char-pack",
  "version": 1,
  "id": "雪见",
  "name": "雪见",
  "created_at": "2026-11-06 14:30:00",
  "app": "WA2-Kazusa-Bot",
  "parts": {"prompt": 6, "worldbook": 1, "memory": 2, "portrait": 278, "voice": 72},
  "files": 360,
  "bytes": 103743189
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `format` | 建议 | 固定 `wa2-char-pack`；用来认「这是不是我们的包」 |
| `version` | 建议 | 格式版本，当前 **1** |
| `id` / `name` | 建议 | 导入时的角色 id 优先级：`id` > `name` > `name.txt` > zip 文件名 |
| `created_at` / `app` / `parts` / `files` / `bytes` | 可选 | 只用于展示和排查 |

**导入端对未知字段一律忽略**，缺字段也不报错 —— 手工做包时 `manifest.json` 可以整个不给。

## 3. 大小与安全

| 限制 | 值 | 为什么 |
|---|---|---|
| 条目数 | ≤ 20000 | 防解压炸弹 |
| 单文件解压后 | ≤ 512 MB | 同上 |
| 总解压大小 | ≤ 2 GB | 同上 |
| 路径 | 必须相对、不含 `..`、不绝对 | 防写到角色目录外 |

解压先落到 `characters/.importing_<时间戳>/`，成功了才原子改名为正式目录 ——
半路失败不会留下半个角色。

## 4. 导入行为

1. 校验（大小 / 路径）→ 剥包装层 → 读 `manifest.json`（可缺）
2. 只解 `PACK_DIRS`（5 个目录）+ `name.txt`，其他条目记进 `skipped` 并回显
3. 角色 id 重名自动加序号（`雪见_2`）
4. 没有 `name.txt` → 用 `manifest.name`
5. `prompt/` 里没有可用的提示词 → 用自带模板 `seed_character()` 铺一份
6. **不自动切换到新角色**（导入完还在原来的角色上）

## 5. 导出时的脱敏（重要）

`memory/standing.json` 里的**关系摘要 / 阶段 / 消息计数**是从真实聊天里长出来的私人进度。
导出时改写成：`relation_summary = ""`、`stage = 1`、`source_msgs = 0`、`updated_at = 导出时间`，
**`fixed`（角色固定设定）原样保留**。原文件不动（导出不改源）。

同理，这些**永远不会进包**：`sessions/`、`config.json`、`prefs.json`、`fewshot.json`、
日志、缓存、`.bak` 备份（旧版提示词里可能有已经改掉的私人内容）。

## 6. 版本兼容策略

- **加字段**（比如 `manifest.license`）→ 不升 `version`，老程序忽略、新程序认得。
- **改语义或删字段** → 升 `version`，并在 `char_pack.import_pack` 里按版本分支。
- 老包永远能被新程序导入（白名单只增不改）。

## 7. 最小可用包

只有 `name.txt` + `prompt/base.txt` 就能导入运行，立绘和语音会自动回落到默认资源。
完整可跑示例见 [`examples/min_pack/`](examples/min_pack/)
（生成脚本 `program/tools/make_min_pack.py`，纯原创内容，可直接跑起来看效果）。

## 8. 校验 / 修复工具

```powershell
# 只检查（不动文件）
python program/tools/char_pack_migrate.py --check 某个角色包.zip

# 修：补 manifest、脱敏 standing、扔掉垃圾条目，输出新包
python program/tools/char_pack_migrate.py --fix 某个角色包.zip --out .\修好的.zip

# 从散文件夹直接打包（自己写角色时最方便）
python program/tools/char_pack_migrate.py --from-dir .\我的角色 --out .\我的角色.zip
```

## 9. 已知缺口

- **读音表 / 翻译术语表不跟着包走**：`pronunciation.json`、`translation_glossary.json`
  在角色目录顶层，不在 `PACK_FILES` 白名单里（`name.txt` 是唯一被打包的顶层文件）。
  换机器后读音和译名要重新导。要做的话：加进 `PACK_FILES` 并升 `version`。
- **立绘命名**：老角色里有 128 张叫「其他N」。程序能显示，但玩家难认；
  新角色建议按 `portrait/<服装>/<表情>.png` 命名。
- **JSON 容忍末尾多余内容**：`worldbook.json` 之类末尾多一行（实测多过一个 `xx`）
  不再导致整本失效 —— 加载器用 `JSONDecoder().raw_decode` 吃掉第一个完整值、忽略其余并记日志。
  但请还是清干净：容忍是为了不让你因为一个笔误丢掉整本书，不是鼓励脏文件。
- **`.bak` / `.bak-日期` / `~$*` / `Thumbs.db` 不会进包**：旧版提示词里可能有已经改掉的
  私人内容，导出时一并过滤（2026-11-06 起）。
- **`portrait/index.json` 可选**：没有时按目录扫（服装 = 子目录，表情 = 文件名），
  所以手工做包不用写索引。
