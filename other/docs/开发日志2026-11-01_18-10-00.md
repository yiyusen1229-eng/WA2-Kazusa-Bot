## 一、做了什么

| 用户要求 | 实现 |
|---|---|
| 存档不许擅自截断，历史必须完整 | `savepages.js` / `game.js` 去掉 `slice(-40)`；`sessions.py` 去掉 `[-60:]` |
| 存档时算 token、超阈值打标记（前端看不见） | `memory.py` 的 `est_messages()`；超了就在存档里写 `memory.enabled=true`，接口返回给前端前会 `pop` 掉 |
| 读档识别标记，改走「记忆书 + 最近一段」 | `/api/session/load` 把 `memory` 接进运行时缓存；`/api/chat` 按 token 决定发多少 |
| 回想界面照常显示全部 | `messages` 原样保存，前端一行没改 |
| 游玩中途也要实时检测、超了自动切换 | 每轮 `/api/chat` 都估算；超阈值就切，条目放**临时缓存**（`cache/memory_runtime.json`，启动时清空） |
| 每 N 轮重新打包一版 | `repack_turns`（默认 6） |
| 全部在后端 | 前端只改了「不截断」两行，界面上看不到任何变化 |

## 二、数据流

```
存档 sessions/<slot>.json
├── messages[]  完整原文（回想用）
└── memory{ enabled, covered_upto, entries[] }   超阈值才有

/api/chat
├─ 估算 token ≤ 阈值  → 原样全发（和以前一样）
└─ 超过阈值 → [人设/世界书] + [记忆条目] + [最近一段原文]
```

**不留空洞**：`covered_upto`（已总结到哪）如果落后于最近段起点，窗口就往前拉到
`covered_upto`，宁可多发几句。反过来，总结超前也没关系（重叠无害）。

## 三、分块打包（第一次跨阈值不卡）

第一次跨阈值时，要折叠的可能是几百条消息。如果一口气塞给模型：慢、贵、还可能超限。
所以 `pack_span()` 按 `chunk_tokens`（默认 4000）**分块**，从最老的未覆盖处往前推；
聊天中途只同步做 1 块（`sync_chunks`），后台做 6 块（`async_chunks`），做不完下次继续。

## 四、踩到的坑：模型输出被 max_tokens 截断 → JSON 解析失败

**现象**：第一次实机测试，存档里 `entries` 一直是 0 条，日志只有「打包中断（0/690）」，
但单独调同一段 API 又完全正常。

**根因**：总结请求的 `max_tokens` 是 700，条目一多，JSON 被截在半句，
`json.loads` 直接失败 → `parse_entries` 返回空 → 整次打包作废。

**修法**：
1. `max_tokens` 提到 1200；
2. `parse_entries` 加兜底：JSON 不完整时用正则扫出所有完整的 `"text"` / `"kind"` 对，
   能救回一条是一条。

**教训**：模型返回结构化数据，**不能只写一条 `json.loads` 就完事**。

## 五、参数（都可以用 `program/memory.json` 覆盖）

| 参数 | 默认 | 说明 |
|---|---|---|
| `cloud_ctx` / `local_ctx` | 32000 / 4096 | 模型上下文；云端和本地差很多 |
| `trigger_ratio` | 0.6 | 吃满 60% 就切换 |
| `recent_ratio` | 0.25 | 「最近一段」占上下文的 1/4（云端 8000、本地 1024） |
| `entries_ratio` | 0.12 | 条目最多占 12% |
| `repack_turns` | 6 | 切换后每 6 轮重新打包 |
| `chunk_tokens` | 4000 | 每块总结多少 token |
| `sync_chunks` / `async_chunks` | 1 / 6 | 前台/后台一次做几块 |

## 六、实测（900 条历史，真实云端模型）

```
存档：memory.enabled=true, covered_upto=690/690, entries=41
聊天：估算 34336 / 阈值 19200 → 只发最近 211 条（共 901 条）+ 41 条记忆
```

条目样例：

- `preference`：和纱多次平静地表示自己记得音乐会的事，并要求玩家不要糊弄过去。
- `event`：玩家在对话中多次提到打工话题并谈自己的想法，近期打算……
- `progress`：对话进行到第 64 句，玩家最近一次谈到下雨……
