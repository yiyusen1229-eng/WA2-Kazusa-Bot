## 版本与更新提示

- 客户端启动 1.2 秒后请求 `/api/update`，后端拉 `version.json` 比对
- 有新版本 → 标题栏出现「发现新版本 x · 点此更新」→ 点击走 `/api/open_url` 打开浏览器
- **发布时必须同时改**：仓库根 `version.json` 的 `version`、`program/src/version.py` 的 `VERSION`
- 本地测试：设 `WA2_UPDATE_URL=http://127.0.0.1:8798/version.json` 指向假版本文件

## 发布流程（约定第 12、13 条）

1. `git tag v<日期>-old`（把当前状态锚住，方便回滚）
2. 把**上一版补丁**合进 `master` 并提交（让 clone 下来就是最新代码）
3. 写**这一轮的更新日志**（单独一份文件，不要追加到旧日志）
4. 生成补丁：`git diff --binary <上一版>..HEAD -- . ":(exclude)other/docs/patches" > other/docs/patches/<日期>_更新补丁.patch`
5. 用临时 worktree 验证补丁能 `--check` 并 `apply`，否则别推
6. 更新 README 的「近期更新」与「文档」表，`git push`（**旧补丁不删**）

## 坑

- 补丁**不能包含 `other/docs/patches/` 自己**（否则每次重生成都在自我膨胀）。
- 补丁基线要写清（日志里写 `A → B`），否则别人不知道先打哪个。
- 探针截图会缩成 391×66，若真要截图就重跑；但默认**不要截图**。
