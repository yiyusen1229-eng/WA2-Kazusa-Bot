# 03 · 记忆 / 世界书 / 人设 / 检索

> 四套东西别混：**人设**（她是谁）、**常驻记忆书**（她本来就知道的事）、
> **世界书**（关键词设定卡）、**对话记忆书**（这一局聊了什么）、**原作片段**（检索）。

## 文件分工

| 文件 | 职责 | 关键函数 |
|---|---|---|
| `memory.py` | 对话记忆书：阈值、打包、条目存储 | `DEFAULTS`、`should_repack`、`pack`、`entries` |
| `standing.py` | 常驻记忆书两段化：固定设定 + 关系摘要（阶段变化时后台刷） | `text`、`build`、`note`、`status` |

| `char_res.py` | 角色资源状态：人设/世界书/记忆书/语音/立绘在哪 | `memory_text`、`prompt_text`、`status` |

## 常驻记忆书（`characters/<角色>/memory/`）

两份东西：

| 文件 | 谁写 | 说明 |
|---|---|---|
| `*.txt`（或 `memory/*.md`） | 用户（特别模式导入） | 老格式：一坨固定设定，每轮原样注入 |
| `standing.json` | 程序（`standing.py`） | 两段化后的格式，存在就优先用它 |

```json
{"version": 1, "fixed": "固定设定（从 *.txt 抄来的，程序之后不再改）",
 "relation_summary": "- 已经确认关系\n- 她开始主动约你", 
 "stage": 3, "updated_at": "2026-11-05 15:20:00", "source_msgs": 88}
```

- **fixed 是用户的**：只在文件不存在时抄一次，之后程序不动；要重抄就删掉 standing.json。
- **relation_summary 只随关系阶段变化刷新**：每个阶段最多一次、阶段 1 不生成、
  失败冷却 30 分钟；失败保留旧版，不阻塞对话。
- 没有 standing.json 或文件坏了 → 回落 `char_res.memory_text()`，注入行为和以前一样。

## 对话记忆书（`memory.py`）默认值

```
cloud_ctx=32000  local_ctx=4096   trigger_ratio=0.6   recent_ratio=0.25
entries_ratio=0.12  max_entries=40  repack_turns=6  max_new_entries=10
```

> 这些数字的区间 / 影响面 / 风险 / 验收方式，以及本机是否被 `memory.json` 覆盖过，
> 看 [`参数与指标.md`](../参数与指标.md)（由 `src/params.py` 生成，`--check` 防过期）。

条目结构：`{text, kind: preference|event|progress, from: [a,b]}`；`progress` 只留最新；
`covered_upto` 是游标；每 6 轮把新折叠的一段压进 `cache/memory_runtime.json`。

## 世界书（`characters/<角色>/worldbook/worldbook.json`）

- 顶层：`scan_depth`(8)、`max_entries`(4)、`max_chars`(1200)、`entries[]`
- 条目：`{name, keywords[], content, priority, period?}`；`period` = `ic|cc|coda|all`（缺省=全放行）
- 只扫**最近 8 条消息**做关键词子串匹配，命中后按 priority 排序截断
- 结构**冻结**（用户要求不改），只加内容

## 人设（`characters/<角色>/prompt/`）

`base.txt` + `stageN.txt` 拼；时期补丁 `persona_ic.txt / persona_cc.txt / persona_coda.txt`
追加在最后并声明最高优先级。

**时期补丁是可选文件，缺了就返回空串**（不是 bug）。写之前先明确四件事：

1. 这个时期她**是谁**（学生 / 在维也纳 / 已回日本）
2. 她**在哪**、和对方关系到哪一步
3. 哪些设定**这个时期还不能用**（最容易写错的地方：把后期的身份提前用掉）
4. 语气差异（高中更冲更绷 / 大学更沉 / 成年更坦白）

写作要点：
- 开头一行写 `【时期：XX · 最高优先级】`，让模型知道这段能覆盖前面的设定；
- **只写边界和状态，不新增剧情**；原作里没有的事一律不编（这条和 `base.txt` 的规则 3 一致）；
- 100~350 字够了。太短没用，太长会把基础人设挤下去；
- 多个结局线仍然只是「另一条线」，补丁里不要写成正在发生。

目前 和纱 的三段（IC 403 字 / CC 360 字 / CODA 448 字）就是按这个写的。
三段的基调是用户定的，以后改的时候别改掉：

| 时期 | 基调（一句话） | 写进去的关键词 |
|---|---|---|
| IC 高中篇 | **装做冷淡**（不是真冷，也不是摆架子） | 怕被看穿、先把「不在意」摆出来、嘴上平心里盯着、被戳破会慌（卡住/转移话题/说反话）、等他转身才敢看背影 |
| CC 大学/出道篇 | **思念成疾、朝思暮想** | 靠钢琴和他「谈着恋爱」、独处时对着空气说话、一提到他就停顿改口、不主动联系但一直在等 |
| CODA 成年篇 | **撒娇最多**（关系已确定） | 贴过去要抱要陪、耍赖、被晾着闹别扭但不真生气、甜话说不出口就用行动代替 |

有个反直觉的点：撒娇在程序里是 <emotion>撒娇</emotion>（BGM 走 warm），补丁里写清楚才有机会
被触发；而 IC 反过来**不该**撒娇，否则三个时期读起来就是同一个人。
另外记住：IC 的「冷」是**装的**——写成真冷淡或大小姐脾气都不对，她是为了护住自己，被戳破时是慌，不是傲慢。
切时期后 system 提示词末尾会换上对应那段，实测 ic/cc/coda 三种人设长度各不相同。`char_res.prompt_text()` 发现 `base.txt` 就返回空
（由 `persona_ctx` 负责拼），别再各拼一套。

## 原作检索（`story_rag.py`）

- **v3 索引**（优先用）`program/src/story_index_v3.json.gz`：**8792 块 / 516.7 万字**，
  每块多带四个标签：
  - `period`：`ic` / `cc` / `coda` / `extra`（特典、后日谈）/ `unknown`
  - `route`：`her`（和纱在场且她戏份不少于雪菜）/ `common`
  - `tags`：情境（亲密 / 调情 / 崩坏 / 拌嘴 / 校园 / 工作 / 离别，可多选）
  - `title`：章节名或特典标题（`特典·6104` 这种）
  - 标签是**启发式**（关键词 + 特典编号），`unknown` 占约三成，别当硬事实用
  - 重建：`python other/dev/work/build_index_v3.py`（读 `L2_scene_final.jsonl`）
- **v2 索引**（回落）`program/src/story_index.json.gz`（4915 块 / 444.8 万字）：
  ```bash
  python program/tools/build_story_index_v2.py --src other/dev/dataset/L2_scene_final.jsonl --chunk 1000
  ```
  两份都要**把 `.gz` 复制到 `build_env/`**（`run_dev` 只同步 `.py`）
- 数据集：`other/dev/dataset/L2_scene_final.jsonl`
  - 主篇：`L2_scene.jsonl`（5618 场景，来自主篇剧本 PDF）
  - 特典 / 后日谈 / 赠品小说：从 `other/dev/game_pak/gh/scripts/*_mix.txt` 的 49 个场景里
    筛出**提到和纱**的 41 个（`other/dev/work/filter_her_scenes.py`），合起来 5659 场景
- 检索时的「偏好」：`memory_context(query, k, max_chars, period=..., tags=...)`
  - 命中同 `period` ×1.3、命中同 `tags` ×1.5，并且**同标签的块优先占位**（避免 H 场景与日常混着抽）
  - `api_chat` 每轮用 `persona_ctx.period_of()` 给 `period`，用 `story_rag.situation_of(用户近三句, loose=True)` 给 `tags`
- 说话风格摘句：`prompt/style.txt`（由 `other/dev/work/extract_style.py` 从 v3 索引按情境摘她的台词生成，
  约 800 字），`persona_ctx.persona_text()` 会把它拼在 base + stage 之后；它是**比较容易读错的参考**，
  只学语气、不照抄。
- 按角色开关：角色文件夹有 `story.json` 且 `enabled:false` → 不检索；有 `story_index.json.gz` → 用角色的
- 改检索参数：k、`max_chars`、分数门槛在 `memory_context` 里

## 坑

- 常驻记忆书是**用户手写**的文件，不要自动生成（会污染人设）。
- 世界书和记忆书**同一事实别写两处**，会双重强调。
- 时期补丁文件不存在时静默跳过（本地目前就没有这三份）。
- v3 索引里的 `period` 是按关键词猜的：`维也纳/斯特拉斯堡/音乐会` 一律算 coda，
  所以 IC 里提到「音乐会」的段落会被误标成 coda。做统计时别拿它当准绳。
- `style.txt` 里的句子是**她说过的话**（逐行识别 `和纱` 行 + 下一行「」），不是旁白；
  改 `extract_style.py` 的 `STRICT` 之后要重新生成，别手改那个文件。
