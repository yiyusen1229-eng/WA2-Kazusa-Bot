# 08 · 代码拆分计划（进行中）

> 目标：把「一个大文件」拆成「一个功能一个文件」，让代理只读需要的那一只。
> 原则：**每拆一步都要跑 6 个自测 + 探针**，拆坏了立刻回滚，不一次性大改。

## 现状（2026-11-04）

| 文件 | 体积 | 问题 |
|---|---|---|
| `program/src/main.py` | **1322 行**（原 1955） | 只剩路由分发 + 静态文件 + 启动；业务已拆到 api_*.py |
| `program/src/ui/game.js` | 68 KB | 演出 + 请求 + 立绘 + 回想 + 音频 + 滚轮/右键 |
| `program/src/ui/opt.js` | 37 KB | 设置页全部逻辑 |

| `program/src/tts_client.py` | 21 KB | 合成 + 参考音频 + 权重切换 |

## 目标结构（后端）

```
program/src/
  main.py            只留：启动、建窗口、起服务（< 300 行）
  text_parse.py      ✅ 已拆：标签拆分 / 日文清理（纯函数）
  rt_cfg.py          路径、prefs、云端配置、模型配置
  chat_llm.py        调云端 / 翻译 / usage / 阶段判断 / 记忆胶水
  api/
    __init__.py
    base.py          static 服务、_json、send_head（Range）
    window.py        /api/window
    text.py          /api/text（字模渲染）
    tts.py           /api/tts、/api/voice/ok
    chat.py          /api/chat
    session.py       /api/session/*
    special.py       /api/special/*、/api/character/*
    scene.py         /api/scene/*
```

Handler 由 mixin 组成：`class Handler(WindowApi, TextApi, TtsApi, ChatApi, SessionApi, SpecialApi, SceneApi, BaseApi)`。

## 目标结构（前端）

```
program/src/ui/
  game.js            [→] 拆成 5 个，共用 window.WA2
    wt-core.js         状态、屏幕切换、常量
    wt-chat.js         发请求、解析标签、打字机
    wt-sprite.js       立绘/服装/场景
    wt-backlog.js      回想、历史、滚轮/右键
    wt-audio.js        bgm / se / 语音音量
  special.js         [→] sp-params.js / sp-char.js / sp-voice.js
  opt.js             [→] opt-model.js / opt-conn.js
```

拆前端的关键：现在各文件都是 IIFE 私有闭包，要先把共享状态挂到 `window.WA2`（一次性成本），
之后按功能搬。**不要先动闭包结构再拆**，容易出隐藏 bug。

## 硬规矩

- 每一拆完就提交，commit 信息写清「拆了什么、测试结果」；拆坏了直接 `git revert`。
- **不改变行为**：只搬代码，不改逻辑；必须改的地方单独一次提交。
- 每次拆完更新本文件「现状」表，标 ✅。
