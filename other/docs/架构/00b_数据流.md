> 架构地图的附页。**改任何一层之前先看这张图**，确认你动的是哪一段、
> 它的上游给了什么、下游等着什么。分层文档见 [`00_总览.md`](00_总览.md)。

## 主链路：一次对话

```
【1 输入】玩家在输入框敲一句
   │  前端 history（全量，前端不裁） + 当前 bg / outfit / period
   ▼  POST /api/chat  {messages, model?, base_url?, memory, bg?, outfit?, period?}
【2 切片】api_chat._chat
   │  ① _memory_context(msgs, 云端?)  超阈值才裁 → 记忆书摘要 + 最近一段原文
   │  ② period = 手动或按 outfit 推断（IC / CC / CODA）
   ▼
【3 提示词】system 按固定顺序拼（顺序就是语义，别打乱）
   │  ① 人设      persona_ctx.persona_text(period)     base + stage + 时期补丁
   │  ② 常驻记忆书 standing.text()                     固定设定 + 关系摘要
   │  ③ 世界书    persona_ctx.worldbook_context()      关键词命中 ≤4 条 / ≤1200 字
   │  ④ 对话记忆书 memory/_memory_context              超阈值才进，≤ 上下文的 12%
   │  ⑤ 原作片段  story_rag.memory_context(q)          像在问剧情才检索，≤900 字
   │  ⑥ 演出标签  api_chat.performance_hints(cc)       场景/服装/情绪/格式（+ 云端：只用日语/双语）
   ▼  messages = [system] + fewshot + 对话历史
【4 模型】云端 /v1/chat/completions  或  本地 Ollama（同一个 OpenAI 兼容形状）
   │  返回原始文本（带标签）
   ▼
【5 拆标签】text_parse
   │  split_thinking → split_emotion → split_scene(<scene>/<outfit>) → split_action → split_bilingual
   │  <zh> 不像中文 或 没有 → translate.py 兜底（云端 → 本地 Hy-MT2 → 空串）
   │  场景文本 → scene_cg.match(scene, prev)  →  CG id（119 张，含时段继承）
   ▼  {reply(日文原文), reply_zh, action, action_zh, emotion, scene, outfit, bg, usage, ms}
【6 演出】前端 wt-chat.send()
   │  语音：speakReply(ja) → /api/tts（按 文本+语种+情绪+参考音频版本 命中缓存）
   │  画面：setBg(bg) → setSpriteByScene(bg, 情绪, outfit) → accumulateMood(zh, emo) 切 BGM
   │  文字：showReply(打字机) + 翻页图标；同时 addHistory 进回想
   ▼
【7 落盘】sessionSave()
   │  sessions/<slot>.json  {schema_version, messages, meta{bg, outfit, thumb, choice}}
   │  缩略图：canvas 截图 → JPEG base64（meta.thumb）
   ▼
【8 缓存】见下表
```

## 缓存表（谁写、key 是什么、怎么失效）

| 缓存 | 位置 | key / 失效 | 谁负责 |
|---|---|---|---|
| 字模图（中文→PNG） | 内存 `_TEXT_CACHE` + 磁盘 `res/assets/ui/text_cache/`（打包版在 `_internal` 下） | 文本 + 字体 + 渲染参数；字体/素材变了整体清空 | `api_text.py` / `main._text_disk_path` |
| 语音 | `cache/tts/`（相对 `tts_client.py`） | 文本 + 语种 + 情绪 + **参考音频版本**（换了音色旧缓存就不命中） | `tts_client._tts_cache_path` |
| 常驻记忆书 runtime | `build_env/cache/memory_runtime.json` | 每次启动清（`_memory.clear_runtime()`） | `memory.py` |
| 关系阶段 | `build_env/cache/persona_stage.json` | 每 40 轮判一次，1~4 封顶 | `persona_stage.py` |
| 价格表 | `build_env/cache/prices.json` | 按天刷新 | `pricing.py` |
| 剧情索引 | `program/src/story_index.json(.gz)` | 由 `build_story_index_v2.py` 生成，**不随对话变** | `story_rag.py` |
| 立绘/背景索引 | 角色 `portrait/index.json`、`res/assets/cg/index.json` | 文件为准；没有 index 时扫目录 | `characters.sprite_index` / `scene_cg.catalog` |
| 素材热重载签名 | 内存（`hotreload._SEEN`） | 只看**素材**：`SKIP_DIRS` 里的运行时目录不参与 | `hotreload.py` |

> ⚠️ 两处缓存路径是「相对 `__file__`」算的（字模、语音），所以开发时落在
> `program/` 下、打包后落在 exe 同级。改这两处之前先确认当前跑的是哪份代码。

## 反向链路：读档

```
/api/session/load?slot=N
  → sessions.py 读 + 版本迁移（schema_version）
  → 前端 __loadSession(): applyHistory → 背景/立绘/最后一句 → 待选分支(meta.choice)
  → 不请求 /api/choice（存过分支就原样摆回来）
```

## 三条容易忘的

1. **提示词顺序 = 语义**：人设在前、演出标签在最后（模型对最后一段更敏感）。
2. **`bg` / `outfit` / `period` 是双向的**：前端把当前值传给后端（用来延续时段、
   推断时期），后端再把模型给的结论传回来。
3. **演出标签的词表要和前端对齐**：`<scene>` 要能在 `scene_cg` 里匹配、
   `<emotion>` 要能在 `wt-sprite.js` 的 `EMO_ALIAS` 和 `wt-mood.js` 的 `EMO_BGM` 里找到。
   改词表 → 三处一起改（`performance_hints` / `EMO_ALIAS` / `EMO_BGM`）。
