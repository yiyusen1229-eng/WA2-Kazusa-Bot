# 02 · 对话管线（一次请求从进到出）

> 入口：`main.py` §7.7 `_chat`。前端：`ui/game.js` 的 `sendMessage`。
> 改这条链上的任何东西，先确认下面 5 步的顺序没被打乱。

## 顺序（system 的拼装顺序就是这个）

```
1. 人设        persona_ctx.persona_text(period=…)     ← base + stage + 时期补丁
2. 常驻记忆书  standing.text()                        ← memory/standing.json（fixed + 关系摘要），没就回落 memory/*.txt
3. 世界书      persona_ctx.worldbook_context(period)  ← 关键词命中，≤4 条 / 1200 字（可被 persona_slices.json 覆盖）
4. 对话记忆书  memory/_memory_context                 ← 超阈值才进，≤ 上下文 12%
5. 原作片段    story_rag.memory_context(q, k=2)       ← 命中才进，≤900 字（可被 persona_slices.json 覆盖）
6. 场景/服装提示（云端时另加语言/格式约束）
```

> **剧情检索（story_rag）的规矩**（2026-11-05 调整）：
> - **只在这句话像在问剧情时才检索**：话里要出现 `STORY_HINTS` 里的锚点
>   （记得 / 以前 / 结局 / 学园祭 / 车祸 / 第二音乐室 / 毕业 …，见 `story_rag.py` 顶部）。
>   闲聊（「今天好冷」「我饿了」）一条不取，避免每句都被塞 900 字剧本。
> - 检索是 BM25 + **汉字二元组**；`df` 按文档去重（以前按出现次数算，会让「雪菜」idf 变负数）。
> - 先走严格档（≥2 个 idf≥3 的词、分数 ≥5）；整句都是常见字时退一档（≥1 个词、门槛 ×0.7），
>   这样「学园祭的演出」「雪菜的车祸」也能命中——这两句以前是 0 命中。
> - 索引块开头带 `〔标题行〕`（场景标题或章节日期），由 `build_story_index_v2.py` 写入。

> **切片预算可配**（#19）：第 3 / 5 步的「条数 / 字数」和常驻记忆上限读
> `perfcfg.slices()`（角色文件夹的 `persona_slices.json`）；没配就是上表的默认值。

请求侧字段：`{messages, model?, base_url?, memory?, bg?, outfit?, period?, voice?}`。

## 关键函数

| 位置 | 干什么 |
|---|---|
| `main.py` §7.7 `_chat` | 组装 system、调云端、拿回复、算花费、返回 |
| `_memory_context`（§6） | 判阈值、发打包请求、返回条目摘要 + 是否触发 |
| `persona_ctx.persona_text` | 人设正文（含 `persona_<时期>.txt` 补丁） |
| `persona_stage` | 关系阶段（每 40 轮判一次，1～4 封顶） |
| `story_rag.memory_context` | 本地 BM25 检索原作块 |
| `game.js` `sendMessage` | 发请求、解析 `<outfit>`/`<action>`/情绪、打字机播放、存历史 |

## 演出侧（前端）

1. 收到回复 → 拆标签（`<outfit>` 换立绘、情绪 → 表情）
2. 中文译文走 `<text>` 字模图（`/api/text`），日文原文走 TTS（`/api/tts`）
3. 打字机播放 + 翻页图标；结束后写回想（`backlog`）与存档

## 双语输出（2026-11-05）

模型现在**一次给两种语言**：`<emotion>…</emotion><action>（中文动作）</action><ja>日语</ja><zh>中文</zh>`。

- `text_parse.split_bilingual()` 拆出 ja / zh（`<jp>`、`<中文>` 这类写法也认）；
  `api_chat` 用 **ja 当日文原句**（→ `reply`、`speak_ja` → TTS），**zh 当字幕**（→ `reply_zh`）。
- 为什么这么干：模型自己知道那句话什么意思，比事后再翻译准得多
  （翻译模型会把 `はるき` 译成「春树」、中→日还满口敬语）；顺带**省掉一次往返**。
- **回落**：模型没给 `<zh>` 或给的不像中文（`text_parse.looks_zh()` 判定）才走 `translate.py`
  翻译层（云端优先 → 本地 Hy-MT2 → 空串）。所以模型偶尔不听话也不影响玩。
- `<action>` 一般直接是中文；只有出现假名时才翻译。

## 坑

- **别在 `_chat` 里塞和对话无关的接口**（历史包袱多，已经 79 KB）。
- 常驻记忆书**每轮都进**，写多了直接推高每轮成本；对话记忆书才是按阈值进。
- `story_rag` 拿最后一条 user 消息当 query，闲聊会被门槛过滤掉（正常现象）。
- 云端回复的 `<outfit>` 只在**换衣服**时才输出，前端靠 `OUTFIT_BY_SCENE` 兜底。
- 计费走 `pricing.py`（含高峰价、cache 命中价），别在前端写常数。
