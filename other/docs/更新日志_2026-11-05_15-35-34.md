## 做了什么

每角色可以带两个配置文件，**只写覆盖值**；不写 = 和以前完全一样。

### `performance.json`（前端演出）

```json
{"fade_ms": 280,
 "mood_to_emotion": {"shy": "sad"},
 "outfit_by_scene": {"夜の学校": "冬季校服"}}
```

- `fade_ms`：交叉淡化时长，夹 200~300。优先级 **内置 240 → 角色配置 → `prefs.xfadeMs`（用户自己调过的最高）**。
- 两张映射表是「内置表 + 覆盖/追加」，不能删内置项；空 = 用 `wt-sprite.js` 自带的表。
- 前端 `ui/wt-perfcfg.js` 暴露 `WA2.perfCfg`：启动拉一次 `/api/performance`，
  `wt-sprite.loadIndex()`（切角色）再拉一次。

### `persona_slices.json`（后端切片）

```json
{"story_k": 3, "story_max_chars": 1000,
 "worldbook_entries": 4, "worldbook_chars": 1400, "memory_max_chars": 800}
```

`api_chat` 的世界书条数/字数、原作检索 k/字数、常驻记忆上限改成读 `perfcfg.slices()`；
默认值就是原来的常量（`test_perfcfg.py` 里钉死了「默认值 = 代码常量」，防止悄悄改行为）。

### 校验：逐字段，不整份丢弃

| 情况 | 结果 |
|---|---|
| 数字超范围 | 夹到边界 + warning |
| 类型不对 / 空串 / bool | 该字段用默认 + warning |
| 不认识的键 | 忽略 + warning（免得以为写了个新开关） |
| 映射表里坏条目 | 丢那一条 + warning |
| 整份 JSON 坏 / 顶层不是对象 | 全默认 + warning |
| 文件不存在 | 默认值，**不算错误** |

warning 会在前端弹一次 toast（之后不重复弹），后端同一条只记一次 WARN 日志。

## 踩到的一处

真机验证时配置完全没生效、还报了一条「读不了」。原因：PowerShell 5.1 / 记事本存出来的
UTF-8 带 BOM，`json.load(encoding="utf-8")` 直接报错，看起来像文件坏了。
改成 `utf-8-sig`（`perfcfg` 和 `standing` 都改了），并加了两条自测「带 BOM 的 JSON 也能读」。
用户手改配置最可能踩这个坑。

## 没做 / 边界

- 映射表不做「删除内置项」，也不做正则/通配，只支持精确键。
- 前端拿到配置有 1 次 fetch 延迟：首帧用内置默认。
- 没做界面上的编辑器：文件就在角色文件夹里，手改即可（改完下一轮生效，不用重启）。
- `fade_ms` 只影响交叉淡化；打字机速度、立绘进出场动画还没做成配置项。
