# 更新日志 · 2026-11-06 11:05 —— 修「背景闪」+「场景/立绘/BGM 不变」

> 实机反馈（用户 2026-11-06 上午，跑的是本地模型 `kazusa14b-v7`）：
> ① 对话界面背景不时闪烁；② 基本没有自动换过场景 CG、立绘和 BGM。
> 四条根因全部在日志/接口里抓到了实证，逐条修。

## 一、背景闪烁：程序自己写的字模缓存被当成了「素材变化」

`hotreload.watch(ASSETS_DIR)` 盯的是整个素材目录，而字模缓存
`assets/ui/text_cache/` **就在这个目录里**，且是程序自己每渲染一句没见过的台词就写一张 PNG。

于是每来一句新台词 → 目录签名变了 → 2 秒后判定「素材变了」→ `gen+1` →
前端 `wt-hotreload.apply()` 调 `__reapplyBg()`（还会重拉立绘索引）→ 背景交叉淡化重画一次
→ **画面闪一下**。

实证（`logs/app-20261106.log`，用户那一局）：

```
[10:23:52] 热重载：assets 变了（第 1 代）
[10:24:00] ...（第 3 代）    ← 70 秒内触发 10 次
[10:24:59] ...（第 10 代）
```

我自己手动请求 2 次 `/api/text`，也立刻多了 2 代：

```
请求前 text_cache 0 个文件 → 请求后 2 个 → 热重载第 1、2 代
```

**修**：`hotreload.SKIP_DIRS` 加上 `text_cache`（和 `sessions` / `cache` / `logs` 同理，
都是运行时数据，不是用户放的素材）。修后复测：连写 3 张新字模，
`/api/hotreload` 的 `gen` 一直 0（4 次轮询都没动）。

## 二、场景 CG 不换：演出标签提示只在「有云端 key」时才会加

`api_chat._chat` 里这段【场景】【服装】【情绪】【格式】提示，以前整个包在 `if cc:` 里
（`cc = cloud_cfg()`，有云端 key 才为真）。用户跑的是**本地 Ollama 模型**，
于是模型从来没被告知要输出 `<scene>`/`<outfit>`/`<emotion>`——
后端 `split_scene` / `scene_cg.match` 再准也没东西可匹配。

**修**：抽出 `api_chat.performance_hints(cc, outfit_hint)`：

- 云端**和本地**都加【场景】【服装】【情绪】【格式】
- 只有【语言】（只用日语）和【双语】（`<ja><zh>`）留给云端——本地小模型做不好双语，
  硬要求反而写坏，中文由 `translate.py` 兜底

## 三、立绘不变：角色包里没有 `portrait/index.json`，索引是空的

角色目录实际长这样（14 套衣服，都是图片）：

```
characters/和纱/portrait/高中·常服/{认真,微笑,生气,冷淡,惊讶,其他,其他2}.png
                        /高中·军装/...
```

**但没有 `index.json`**（老版本导入的角色包不写），`characters.sprite_index()`
于是返回空 → 前端 `SPRITE_INDEX` 空 → `spritePath()` 每套衣服都查不到 →
`return "assets/kaz_cold.png"` 永远同一张。

实证：修前 `/api/character/sprite/index.json` 返回 `outfits: {}`；
修后返回 **14 套**，每套几十个表情。

**修**：`characters._scan_portrait_outfits()` —— 索引为空时照
`portrait/<衣服>/<表情>.png` 现扫一份（不写文件，加了图下次自动生效）。
写了 `index.json` 的仍以文件为准（那里有扫不出来的 code/label/variants）。

顺带修了一个合并 bug：自带索引按编号、角色索引按中文名时，改名分支把
**自带那套的表情映射整段丢了**（注释写着要叠加，代码读的是新 key 的位置）。
`test_sprite_scan.py` 的第 3 组用例盯住了这条。

## 四、表情永远同一张：情绪名跟素材对不上

模型给的 `<emotion>` 是 `calm / soft / 毒舌 / 撒娇 / 哭腔 / 调侃吐槽 / 问句`，
程序 `detectMood` 给的是 `angry/sad/warm/smile/cold`，
而素材里的表情名是中文：`认真 / 微笑 / 生气 / 冷淡 / 惊讶 / 害羞 / 难过 / 其他`。
`MOOD_TO_EMO` 里映射的是 `angry→"angry"` 这种英文名，素材里没有 → 退「认真」→
**换情绪等于没换**。

**修**：`wt-sprite.js` 加 `EMO_ALIAS`，按顺序逐个试（原名 → 角色覆盖表 →
`MOOD_TO_EMO` → 别名），命中就用：

| 给的 | 用素材里的 |
|---|---|
| `calm` / `问句` | 认真 |
| `soft` / `warm` / `smile` / `撒娇` / `调侃吐槽` | 微笑 |
| `毒舌` / `cold` | 冷淡 |
| `angry` | 生气 |
| `sad` / `哭腔` | 难过 |
| `惊讶` / `shy` | 惊讶 / 害羞 |

## 五、BGM 不变：`detectMood` 是全中文正则，却喂了日语原文

`accumulateMood(reply)` 里的 `reply` 是**日语原句**，而 `detectMood()` 的关键词
（滚/烦/早点睡/对不起…）全是中文，日语原文一个都不命中 → 永远返回 `calm` →
累积氛围永远是 calm → `best !== currentBgmMood()` 恒假 → **BGM 一辈子不换**。
（双语改造之前 `reply` 是中文译文，所以以前是好的。）

**修**：`accumulateMood(replyZh || shown)`，有中文字幕就喂中文。
切换门槛没动（0.65 衰减 + 连续两轮领先 2 分），避免单句抽风跳歌。

## 要注意

- **本地模型现在也会收到【场景】【服装】【情绪】**：小模型的输出会更啰嗦一点，
  但这是演出能跑起来的前提。如果发现本地模型开始乱塞标签，
  别删提示，改 `scene_cg.prompt_hint()` 的措辞。
- 老角色包**不用重新导入**：索引是读的时候现扫的。
- 字模缓存目录位置没动（仍在 `assets/ui/text_cache`），只是不再参与素材签名。
