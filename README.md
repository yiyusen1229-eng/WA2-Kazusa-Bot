# AI 聊天界面架构 · AI Chat UI Architecture

> **本项目全部由 AI 制作**：从第一行代码到这份 README，100% 由 AI 生成。
> 人类负责提出需求、提供素材、测试验收。

一个**可插拔的桌面 AI 聊天界面框架**：把「界面层、对话层、语音层、资源层」拆开，
界面用 800×450 的固定舞台做像素级排布，资源（背景、立绘、图标、音效、字体）全部由使用者自行接入。

> **这是一个界面框架，不是一个作品。**
> 仓库只包含源代码与文档：**不含任何图片、音频、字体、模型或第三方素材**。
> 你往 `resources/` 里放什么，它就长什么样。

## 它解决什么问题

做桌面 AI 聊天程序时，真正的麻烦不是调模型，而是这些：

| 问题 | 本项目的做法 |
|---|---|
| 界面要精确到像素，但窗口大小可变 | 固定 800×450 舞台 + `transform: scale()` 等比缩放，坐标一处写死、处处一致 |
| 中文小字要清晰、要能描边、要跟上主题色 | 后端把文字渲染成 PNG（字模优先，系统字体兜底），前端只贴图 |
| 无边框窗口的拖动、最大化、贴边 | 后端线程跟随光标，前端零计算 |
| 素材随时替换，不想改代码 | 资源按约定命名丢进目录，清单文件驱动，不改代码 |
| 语音/翻译/对话模型想换就换 | 三个服务都走 HTTP 接口，只改配置 |

## 架构

```
┌───────────────────────────────────────────┐
│ 界面层  pywebview + WebView2（800×450 舞台） │
│   标题 / 对话 / 存档 / 回想 / 设置 / 模型管理   │
└───────────────┬───────────────────────────┘
                │ HTTP（本机随机端口）
┌───────────────┴───────────────────────────┐
│ 服务层  Python 单进程 http.server            │
│   /api/text    文字 → PNG（字模渲染）         │
│   /api/tts     文本 → wav（TTS 服务）         │
│   /api/chat    对话（任意 OpenAI 兼容接口）    │
│   /api/session 存档 / 读档 / 缩略图           │
│   /api/window  无边框窗口控制                 │
└───────────────┬───────────────────────────┘
                │
┌───────────────┴───────────────────────────┐
│ 资源层  resources/（使用者自备）              │
│   背景、立绘、图标、音效、字体、清单            │
└───────────────────────────────────────────┘
```

**三层之间只有接口，没有耦合**：换界面不影响服务，换模型不影响界面，换素材不影响代码。

## 快速开始

```bash
cd program/src
python -m venv venv && venv\Scripts\activate
pip install -r requirements.txt
python main.py                 # 开窗口
python main.py --serve-only    # 只起后端（调接口用）
```

资源缺失时会自动使用占位素材（纯色块 + 系统字体），**逻辑全部可跑**。

## 资源接入

界面不认"哪个作品"，只认**文件名与清单**。把资源按约定放进目录即可：

```
program/res/assets/
├── ui/        界面图集与按钮
├── snd/       音效（点击、悬停、取消…）
├── bgm/       背景音乐
├── char/      立绘
└── bg_*.png   背景
```

详见 [other/docs/资源接入.md](other/docs/资源接入.md)。

> **关于素材来源**：本项目不提供、不下载、不附带任何素材。
> 你使用什么资源、从哪来、是否有权使用，**完全由你自己负责**——本项目只提供界面与代码。

## 可以换成什么

这套框架不绑定任何特定角色或作品，你可以：

- 换成任意角色的立绘与语音
- 换成任意风格的主题（改 CSS 变量与切图）
- 换成任意对话后端（OpenAI 兼容接口、本地模型、自建服务）
- 换成任意 TTS，只要提供 `文本 → wav` 的 HTTP 接口

## 设计取舍

- **文字走图片**：牺牲了可选中/可复制，换来与图集完全一致的字形、描边与字距
- **舞台坐标写死**：牺牲了响应式，换来像素级稳定
- **单进程 http.server**：牺牲了并发，换来零依赖与易部署（本地单用户场景够用）
